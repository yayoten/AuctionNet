# 研究の進め方で守ること

実験を設計するとき、REP を立てるとき、報告を書くときに守ること。
仮説そのものの書き方（仕組みを述べる、対立仮説を並べる、中間の量で確かめる）は、`.claude/rules/hypothesis_and_verification.md` に従う。この資料は、その手前にある「どういう順で、どういう細かさで進めるか」を決める。

> 2026-10-08 作成。ユーザーが口頭で述べた方針（指導教員の評価の観点を含む）を、Claude がまとめた。もとの発言は `research/W001_既存手法の比較/chat_with_claude/6_最初の実験設計の案_超過が生じる段の切り分け.md` の 1 節。

## 1. 一番大事なこと

**仮説そのものより、その仮説に至った筋道が評価される。** 結果が良くても、そこに至る筋道が無い案は、評価されない。

| 評価されない進め方 | 理由 |
|---|---|
| 思いつきの案を試す | なぜその案なのかを、手元の事実から説明できない |
| 先に実験し、結果を見てから仮説を当てはめる | 後づけの説明は、見抜かれる。仮説が外れる余地が無かったことになる |
| うまくいく前提で、先の計画まで書く | 外れたときにどうするかを、考えていないことになる |

## 2. 骨子は大まかに、ステップは細かく

- **骨子（最終的に何を明らかにしたいか）は、先に決める。** 骨子が無いと、仮説がどこへ向かうのか分からず、実験が発散する。骨子は、先行研究の調査から立てる（`chat_with_claude/` の資料）。
- **骨子は大まかでよい。** 細かく決めるのは、次の 1 ステップだけである。
- **1 ステップの仮説と検証は、単純でよい。** 凝った仮説を 1 つ置くより、単純な仮説を細かく積む。
- **各ステップは、骨子のどの部分を進めるものかを書く。** 書けないステップは、やらない。
- 骨子を変えるときは、理由と日付を `MASTER.md` の「判断の履歴」に残す。

## 3. 仮説には、根拠を必ず付ける

仮説を書くときは、「なぜそう考えたか」を、次の 3 種類の材料に分けて書く。材料が 1 つも無い仮説は、立てない（探索にする）。

| 材料 | 例 | 書き方 |
|---|---|---|
| 確認した現象・過去の実験結果 | REP001 の「ペナルティを受けたセルは PID 82%」 | REP の ID と数値を付ける |
| コードを読んで分かる事実 | 「落札したら次点の入札額を払う」 | ファイル名を付ける。仮説にしない |
| 理論・先行研究 | 「違反は予測誤差に比例する」（GRM の定理） | 出典を付ける。読んだ範囲も書く |

- 根拠から仮説までを、**「A である。B である。だから C と考えた」**と、飛ばさずに書く。
- 根拠のうち、確かめていないもの（推測、他人の報告の伝聞）は、確かめたものと分けて書く。
- 前の REP の結果を仮説づくりに使ったときは、そう明記する（`research/README.md` 6.2）。

## 4. 外れたときのことを、先に書く

- 実験の前に、**起こりうる結果を全部並べる。** 仮説が支持される場合だけでなく、対立仮説が支持される場合、どれとも言えない場合、測定そのものが成り立たない場合も書く。
- それぞれの結果について、**何が分かったことになるか**と、**次に何をするか**を書く。
- 「〜になるはずなので、次は〜する」のように、1 つの結果だけを前提にした計画を書かない。先の計画は、「この結果なら、こちらへ進む」という枝で書く。
- 前の REP が終わっていないのに設計するときは、**前提にした結果**を明記し、その前提が崩れたときに設計のどこを変えるかも書く。

## 5. 1 ステップの書き方

REP を設計するときは、次の順で書く。報告で話す順も、これと同じにする。

| 順 | 項目 | 書くこと |
|---|---|---|
| 1 | 知りたいこと | 何が分からないのか。骨子のどの部分か |
| 2 | 手元にある材料 | 現象・過去の結果・コードの事実・理論（3 節の区別つき） |
| 3 | そこから考えたこと | 材料から仮説までの筋道。対立仮説も同じ材料から立てる |
| 4 | 確かめ方 | 何を変え、何を測るか。仮説どうしで違って見える中間の量。捨てる基準 |
| 5 | 起こりうる結果と、その先 | 結果ごとに、分かることと次の一手（4 節） |
| 6 | 結果 | 事実だけ（実験のあと） |
| 7 | 考察 | 判断と、言える範囲。次の問い（実験のあと） |

- 1〜5 は、実験の前に書いてコミットする（`research/README.md` 9.）。
- 4 の仮説の枠は、`hypothesis_and_verification.md` の 4 節を使う。

## 6. 書いたあとの確認

- [ ] このステップが、骨子のどの部分を進めるかを書いたか
- [ ] 仮説の根拠を、現象・コードの事実・理論に分けて、出どころ付きで書いたか
- [ ] 根拠から仮説までに、飛びが無いか
- [ ] 仮説と検証は、1 つに絞った単純なものか
- [ ] 結果を見る前に書いたか（後づけになっていないか）
- [ ] 支持される場合以外の結果と、そのときの次の一手を書いたか
- [ ] 終わっていない REP の結果を前提にしたとき、その前提と、崩れたときの扱いを書いたか
