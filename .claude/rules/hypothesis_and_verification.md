# 仮説と検証の書き方

研究で仮説を立てるとき、検証の計画を書くとき、進め方の資料を書くときに守ること。
`research/README.md` の「2. 基本の考え方」を、仮説と検証について詳しくしたもの。

> 2026-10-08 作成。Web 検索で調べた科学の方法の考え方（反証可能性、強い推論、複数の作業仮説、操作の確認）と、ユーザーの指摘をもとに、Claude がまとめた。出典は末尾。

## 1. 一番大事なこと

**「やってみたら成績が上がった」は、仮説の検証ではない。** それは、アイデアが効いたことを示すだけで、なぜ効いたかを示さない。

仮説の検証は、**仕組みの途中にある量**が、仮説の言うとおりに動いたかを見ることで行う。最終の成果（score、制約の超過率など）は、検証の指標にしない。

```
操作（原因と考えるものを変える）
   ↓
中間の量（仕組みが正しければ、こう動くはずの量）   ← 検証はここで行う
   ↓
最終の成果（score、超過率）                      ← 報告はするが、判断には使わない
```

## 2. 仮説とは何か

仮説は、次の 4 つを満たす文である。

| 条件 | 意味 | 確かめ方 |
|---|---|---|
| **現象の言い換えではない** | 見えたことを、別の言葉で繰り返していない | 仮説の文を消しても、現象の説明から情報が減らないなら、言い換え |
| **仕組みを述べている** | 何が、どういう経路で、その現象を起こすかを言っている | 「なぜ」に答えているか。「何が起きたか」だけなら観測 |
| **まだ見ていないことを予測する** | 仮説が正しければ見えるはずの、新しい観測を導ける | 予測を 1 つ以上、具体的な量で書けるか |
| **外れうる** | どんな結果が出たら捨てるかを、先に言える | 「どんな結果でも説明できる」なら、仮説ではない |

**言い換えの例（悪い）**

- 現象：「CPA 制約を超えるセルが多い」
- 仮説：「制約を入札に使っていないから、制約を超える」

これは、ほぼ言い換えである。「使っていない」ことはコードを読めば分かる事実で、「だから超える」は、仕組みを言っていない。どういう経路で超えるのか（どの機会を、いつ、なぜ買ってしまうのか）が抜けている。

**仕組みを述べた例（良い）**

- 仮説：「入札係数 α が制約 C を超えている時間帯に買った分が、1 日の平均の購入単価を C より上に引き上げる。α が C を超えるのは、予算の消化が遅れたときに α を上げる規則が働くからである」
- 予測：α が C を超えた時間帯の支出の割合が大きいセルほど、期待 CPA が C を大きく超える。α が C を超える時刻は、消化の遅れの判定が続いた後に来る。
- 捨てる基準：α が C を超えた時間帯の支出の割合と、期待 CPA の超過に、関係が無い。

## 3. 検証とは何か

### 3.1 対立する仮説を並べる

1 つの仮説だけを持つと、それを支持する結果ばかりを探してしまう。**最初から、対立する説明を複数並べる。**

- 現象を説明できる仮説を、2 つ以上書く。
- それぞれが正しいとき、**同じ観測がどう違って見えるか**を書く。
- 違って見える観測を選んで、実験にする。

**どの仮説が正しくても同じ結果が出る実験は、検証にならない。** 「制約の上限を足したら超過が減った」は、ほとんどの仮説のもとで起きるので、仮説を区別しない。

### 3.2 検証の指標は、中間の量で置く

| | 内容 | 例 |
|---|---|---|
| 操作の確認 | 変えたつもりのものが、本当に変わったか | 上限を足したあと、α が実際に上限以下になっているか |
| **中間の量** | 仕組みが正しければ動くはずの量が、予測どおりに動いたか | 割高な機会への支出の割合、α の時間変化、購入数のぶれの大きさ |
| 最終の成果 | score、超過率 | 報告する。仮説の判断には使わない |

- 中間の量は、**仮説ごとに違うものを選ぶ**。全部の仮説で同じ量（score）を見ない。
- 最終の成果が良くなっても、中間の量が予測どおりでなければ、仮説は支持されていない（別の理由で良くなった）。
- 最終の成果が良くならなくても、中間の量が予測どおりなら、仮説は支持されている（仕組みは合っているが、成果に効く別の要因がある）。

### 3.3 予測は、向きではなく、形で書く

「増える」「減る」という向きだけの予測は、当たりやすく、仮説を区別しない。**どの条件で、どのくらい、どういう関係で**、を書く。

| 弱い予測 | 強い予測 |
|---|---|
| ぶれがある | ぶれの大きさは、期待購入数 N の平方根に反比例し、手法に依らない |
| 超過が減る | 超過のうち、α が C を超えた時間帯の支出で説明できる分が、手法ごとに決まった割合になる |
| 成績が上がる | 最適な余裕は、N が大きいほど 0 に近づく |

形の予測は、外れたときに「どこが違ったか」が分かる。

### 3.4 捨てる基準を、先に書く

- 結果を見る前に、「この結果なら、この仮説を捨てる」を書く。
- 数値の基準は、REP を作るときに決め、コミットしてから実験する（`research/README.md` の 9.）。

## 4. 資料に書くときの決まり

進め方の資料、REP の md、報告に、仮説と検証を書くときは、次を守る。

1. **「期待する結果」を、向きつきで書かない。** 「超過が減る」「成績が上がる」「優位が縮む」のような書き方は、後の実験の見方を引っ張る。
2. 代わりに、**「区別する観測」**を書く。仮説が正しいときと、対立仮説が正しいときに、中間の量がそれぞれどう見えるかを、並べて書く。
3. 仮説は、次の枠で書く。

   | 項目 | 書くこと |
   |---|---|
   | 現象 | 観測した事実（REP の ID つき） |
   | 仮説 | 仕組みを述べた 1 文 |
   | 正しければ見えるはずのもの | 中間の量についての、形の予測 |
   | 対立仮説なら、どう見えるか | 同じ中間の量が、別の説明ではどうなるか |
   | 捨てる基準 | どの結果なら捨てるか |
   | 最終の成果 | 何を報告するか（判断には使わない、と明記） |

4. **恒等式による分解は、仮説ではなく、測定である。** 例：「実績 CPA ÷ 制約 = 買い方の因子 × 抽選の因子」のように、定義から必ず成り立つ分解は、検証ではない。どの因子が大きいかを測る道具として使い、仮説は、各因子が**なぜその大きさになるか**について立てる。
5. コードを読めば分かることは、仮説にしない。事実として書く。

## 5. 書いたあとの確認

- [ ] 仮説は、現象の言い換えになっていないか
- [ ] 仮説は、仕組み（経路）を述べているか
- [ ] 対立する仮説を、2 つ以上並べたか
- [ ] 検証の指標は、中間の量か。score や超過率で判断していないか
- [ ] 選んだ観測は、仮説どうしで違って見えるか
- [ ] 予測は、向きだけでなく、形（条件、大きさ、関係）で書いたか
- [ ] 捨てる基準を、結果を見る前に書いたか
- [ ] 「〜が減る」「〜が上がる」のような、向きつきの期待を書いていないか

## 6. もとにした考え方

| 考え方 | 内容 | この資料での使い方 |
|---|---|---|
| 反証可能性（Popper） | 科学的な主張は、それを誤りと示しうる観測がある | 「外れうる」「捨てる基準を先に書く」 |
| 複数の作業仮説（Chamberlin）、強い推論（Platt, 1964） | 対立仮説を並べ、どれかを排除できる決定的な実験を選び、繰り返す | 「対立する仮説を並べる」「区別する観測を選ぶ」 |
| 操作の確認、媒介する変数（実験計画） | 操作が効いたかを別に測る。仕組みを言うには、途中の変数を測る、または直接操作する | 「検証の指標は、中間の量で置く」 |
| 「イシューからはじめよ」（安宅和人） | 良い問いは、答えが出ると先の方向が変わり、踏み込んだ仮説があり、今の手段で答えを出せる | 「現象の言い換えではない」「スタンスを取る」。ユーザーが挙げた本。Claude は要約記事しか見ていない |
| 機械学習の実験への批判（アブレーションの限界） | 部品を外して成績を見るだけでは、仕組みの説明にならない | 「成績が上がった、は検証ではない」 |
