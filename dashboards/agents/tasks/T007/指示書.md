# T007 確定した設定での評価の流し直し（864 run）の準備と実行

> 無人で動く Claude への指示書。起動した Claude は、まず `経緯.md`（このタスクができるまでの流れ）、次にこの文書と `.claude/rules/unattended.md` を読む。
> 進み具合は、下のチェックリストに印を付け（`- [x]`）、`進捗.md` に書く。画面の「進み具合」は、この印の数で出る。**前の進捗は `進捗_旧.md`（参考）。この文書の内容が正である。**
> **モデルと effort：Sonnet・medium。`high` は使わない（ユーザーの決まり、2026-10-11）。**
> **このタスクは、「準備して、実行を AI なしのスクリプトに任せ、会話を終える」ところまで。** 実行を待つ間、AI を動かさない（トークンの節約）。実行が終わると、スクリプトが T011（照合と REP の仕上げ）を起動する。

## 目的

T003・T004 で流した評価（確定した設定。ルールベース 3 手法・学習ベース 5 手法）を、**T006 の細かい記録つきで、864 run 流し直す**。T009 の新しい DB に入れ、T010 の負荷を見るランナーで、**メモリ・CPU とも約 90% までの並列で、速く**流す。その準備（spec、パイロット、実行計画）をし、実行を、**AI を使わないシェルスクリプト**に任せる。

## 進め方の決まり（このタスク固有）

1. **前提：T009 と T010 が完了していること。** 最初に `agentctl.py list` で確かめる。完了していなければ、`進捗.md` に書いて止める。
2. 最初に、`経緯.md`、この文書、`.claude/rules/unattended.md`、`CLAUDE.md`、`research/README.md`（8.）、`DB/README.md`（T009 で作り直された構造。版・段・`params` の台帳・`experiments`）、`DB/記録の一覧.md`、`dashboards/agents/tasks/T009/進捗.md`・`T010/進捗.md`（ランナーの使い方、並列数の実測）、`再実施_学習ベース/params/` の spec を読む。`python3 dashboards/programs/agentctl.py list` と `git status` で、他のタスクと他の Claude の未コミットの変更を確かめる。
3. **流す run：864 run。**

   | 群 | 内訳 |
   |---|---|
   | ルールベース | PID・ABid・Online LP（設定は `baseline_params.json` の `rule_based`。既定値）× 48 位置 × エピソード 0〜3 = 144 run |
   | 学習ベース | BC・IQL・CQL・BCQ・TD3_BC × seed 1〜3（重みは `baseline_params.json` の `learned`。`DB/models/` にある）× 48 位置 × エピソード 0〜3 = 720 run |

   spec は、T004 の `再実施_学習ベース/params/eval_*_s{1,2,3}.json`・`eval_rule_based.json` を**もとに**、`再実施_学習ベース/params_v3/` に新しく作る（もとの spec は書き換えない）。変えるのは、`"rep"` を新しい名前（ルールベースと学習ベースで別。たとえば `rerun_rule`、`rerun_learned`）にすることと、`"record"` の段だけ。**`rep` の名前を、過去の名前（`REP001`〜`REP005`、`REP002new`、`REP003new`、`rerun_*_v2`）と重ならないようにする。** 付けた名前と、T009 の台帳が振った `param_id`（P…）を、`進捗.md` に書く。
4. **記録の段：detail を全 864 run、full を 8 run（8 手法 × 位置 0 × seed 1）**（Claude の判断。要確認。経緯 5）。T006 の実測は、detail 約 92MB/run、full 約 481MB/run（PID）。学習ベースは、**最初の数 run で実測して**、全体の見積もり（容量・時間）を `進捗.md` に書く。容量（`du -sh .`）が **350GB を超える見積もり**になったら、段を下げる（standard にする）。
5. **コードを変えない。** 流す前に、`git status` で、`github/` と `research/src/` に未コミットの変更が無いことを確かめる（`github_dirty` = false で記録するため）。変更があり、自分のものでなければ、触らず、**流さずに止める**。
6. **パイロット。** 本番の前に、数 run（ルールベース 3 手法と、学習ベース 5 手法を、1 位置ずつ。4 エピソード）を、T010 のランナーで流し、`status` = ok、DB に入る、`param_id` が付く、1 run の大きさと時間、を確かめる。
7. **実行は、AI なしのスクリプトに任せる。**
   - `再実施_学習ベース/programs/run_chain_v3.sh`（名前は担当が決めてよい）を作る。内容は、次の 2 段。
     1. T010 の負荷を見るランナーで、864 run（と full の 8 run）を流す（メモリ・CPU とも約 90% まで。スワップを使い始めたら投入を止める）。
     2. 終わったら、新しい DB から、`rep` の新しい名前の run の数と `status` を数える（`programs/count_runs.py` など）。**864 run がすべて ok のときだけ**、`python3 dashboards/programs/agentctl.py launch T011` を実行する。そうでなければ、`進捗.md` に、足りない run の数・失敗の内訳を追記して終わる（T011 は起動しない）。
   - `setsid nohup bash run_chain_v3.sh > …/chain.log 2>&1 &` のように、**このタスクの会話が終わっても動き続ける形**で起動する。`pgrep -f` で確かめるときは、自分に一致しない書き方（`[r]un_chain_v3` のように）にする。
   - 起動したら、数分待って、run が DB に増えていること、並列数・メモリ・CPU が想定どおりであることを確かめ、`進捗.md` に書く。**そのあと、会話を終える（`done T007`）。実行の終わりを、待たない。**
   - 審査で、バックグラウンドの起動が止められたら、回り道を探さず、`進捗.md` に書いて止める（ユーザーに頼む）。
8. **コミット。** 区切りごとに、自分が変えたファイルを名前で指定する（spec・programs）。`git -c user.name=yayoten -c user.email=g2222077@tcu.ac.jp commit …`。**push はしない**。1 ファイル 50MB を超えるものを、コミットしない。他の Claude・ユーザーの未コミットの変更に触らない・巻き込まない。
