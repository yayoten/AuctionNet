# T011 T007 の結果の照合と、再実施の 2 つの REP の仕上げ

> 無人で動く Claude への指示書。起動した Claude は、まず `経緯.md`（このタスクができるまでの流れ）、次にこの文書と `.claude/rules/unattended.md` を読む。
> 進み具合は、下のチェックリストに印を付け（`- [x]`）、`進捗.md` に書く。画面の「進み具合」は、この印の数で出る。
> **モデルと effort：Opus・medium。`high` は使わない（ユーザーの決まり、2026-10-11）。**

## 目的

T007 が流した 864 run（ルールベース 144 + 学習ベース 720、細かい記録つき。DB は T009 の新しい構造）の結果を、**前の結果と照合**し、**再実施の 2 つの REP を仕上げる**（`再実施_ルールベース/REP.md`・`.tex`・`.pdf`、`再実施_学習ベース/REP.md`・`.tex`・`.pdf`）。終わったら、T008（REP006 の解析）を起動する。

## 進め方の決まり（このタスク固有）

1. **前提：T007 が完了し、864 run がすべて ok でそろっていること。** 最初に `agentctl.py list`、T007 の `進捗.md`、DB で確かめる。そろっていなければ、`進捗.md` に書いて止める。
2. 最初に、`経緯.md`（T007 と共通の背景。全部読む）、この文書、`.claude/rules/unattended.md`、`CLAUDE.md`、`research/README.md`（特に 6.3、8.、9.）、`DB/README.md`（T009 の新しい構造）、`DB/記録の一覧.md`、`research/W001_既存手法の比較/REP番号の対応表.md`、`再実施_ルールベース/REP.md`、`再実施_学習ベース/REP.md`、`dashboards/agents/tasks/T007/進捗.md`（`rep` の名前、`param_id`、実測、見積もり）、`.claude/commands/make_progress_report.md` を読む。`agentctl.py list` と `git status` で、他のタスクと他の Claude の未コミットの変更を確かめる。
3. **前の結果との照合。** 新しい run は、前の run と**同じ設定・同じ重み・同じ位置・同じエピソード**なので、結果が一致する見込みである。`episodes` の `reward`・`all_cost`・`score_component` を、セルごとに比べる。前の run は、`DB/_legacy/`（T009 が退避。読むだけ。書き換えない）。

   | 比べる相手 | 内訳 |
   |---|---|
   | ルールベース 144 run | T003 が判定に使った旧 Linux の 144 run（旧 DB の `rep` = REP002）。無ければ、T006 の版 2 の 18 run |
   | 学習ベース | T004 が流した 661 run（旧 DB の `rep` = REP003new）。`DB/_legacy/` にある範囲 |

   一致しないセルがあれば、**止めずに**、セルの数・手法・位置・差の大きさを表にして `進捗.md` に書く（考えられる原因が分かれば書く。追究は、別）。
4. **記録の整合。** `ticks` の合計 = `episodes`、`agent_ticks`・`pv_won` の合計 = `ticks`（`DB/記録の一覧.md` の確認の項目）を確かめる。
5. **再実施の 2 つの REP を仕上げる。**
   - 新しい 864 run は、ルールベース・学習ベースとも**同じ `github_version`** なので、「同じ版の run でそろえて比べる」という事前の決まり（`REP.md` 3.2 節）を満たす。この 864 run を、**結果として使う**。
   - `再実施_学習ベース/programs/analyze.py`、`再実施_ルールベース/programs/analyze.py`（集計の定義は `REP.md` 4.1 節。**結果を見てから変えない**）を、新しい DB（`rep` の新しい名前）で動かせるように直す（定義は変えない。T007 が直していれば、それを使う）。ルールベースの `REP.md` は、結果の節の「結果として使う run」を、新しい 144 run に書き換え、前の 144 run との照合の結果を足す（判定の基準は、すでに事前に書かれている。動かさない）。
   - 学習ベースの `REP.md` は、事前記録のとおり、結果・判断・得られた事実・結果から生まれた問い・未確認事項を書く。報告（tex・PDF）は、`.claude/commands/make_progress_report.md` に従って作る（**探索型の PDF には、「結果から生まれた問い」を書かない。式には番号を付け、文中で「式(N)」と言及する。文章は短く**。`research/README.md` 6.3）。PDF は、画像にして目で確かめるのは、最後の 1 回だけにする（途中は `pdftotext` で確かめる）。
   - 版が変わった理由（記録の追加、高速化。照合の結果）を、両方の `REP.md` の「実験の記録」に足す。**達成条件・判断指標・集計の定義は、動かさない。**
6. **コミット。** 区切りごとに、自分が変えたファイルを名前で指定し、種類で分ける（programs／REP の md・tex・PDF）。`git -c user.name=yayoten -c user.email=g2222077@tcu.ac.jp commit …`。**push はしない**。1 ファイル 50MB を超えるものを、コミットしない。他の Claude・ユーザーの未コミットの変更（`CLAUDE.md`、`.claude/`、`dashboards/`、`research/MASTER.md` など）に触らない・巻き込まない。
7. **新しい run を流さない。** データが足りなければ、止まって `進捗.md` に書く。
