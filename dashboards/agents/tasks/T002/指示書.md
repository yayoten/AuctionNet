## json の形（Claude の案）

`research/src/baseline_params.json`。1 つの手法に 1 項目。次の REP が、この 1 ファイルから設定を引く。

```json
{
  "version": 1, "decided_in": "REP003", "decided_at": "2026-10-xx", "commit": "<確定したコミット>",
  "note": "以後の比較に使う、既存手法のベースライン設定。決め方は REP003.md",
  "rule_based": {
    "PID": {"kwargs": {}}, "ABid": {"kwargs": {}}, "OnlineLP": {"kwargs": {}}
  },
  "learned": {
    "BC": {"train": {"step_num": 0, "seed": 1, "threads": 1, "other": {}}, "model_dirs": {"1": "DB/models/M..."}},
    "...": "5 手法すべて"
  },
  "evaluation": {"episodes_train_free": [4, 5, 6, 7], "note": "設定の選択に使った日。評価の日（0〜3）は選択に使っていない"}
}
```

- `kwargs` が空なら、既定値のまま、の意味。
- 形は、実装の都合で変えてよい。変えたら、理由を `進捗.md` に書き、テストを合わせる。

## 実行上の注意

- 学習も評価も CPU（`CUDA_VISIBLE_DEVICES=""`。実行スクリプトが設定する）。ロックの torch は、この端末の GPU で計算が落ちる。
- 同時に走らせるのは、**8 プロセスまで**（1 本 約 2.5〜3GB。メモリ 32GB）。学習と評価を同時に流すときは、`free -g` で空きを確かめてから。
- BCQ の学習は重い（1 ステップ 約 0.4 秒、スレッド 4 で約 0.14 秒）。`threads` は `model_id` に入る。
- Python は `.venv/bin/python`。テストは `github/Test/…` で `../../../.venv/bin/python -m pytest`。
- コミットは区切りごとに小さく、**自分が変えたファイルを名前で指定する**。`git push` はしない。
