# T008 REP006 の解析（超過の三つの指標 E・P・L への分解）

> 無人で動く Claude への指示書。起動した Claude は、まず `経緯.md`（このタスクができるまでの流れ）、次にこの文書と `.claude/rules/unattended.md` を読む。
> 進み具合は、下のチェックリストに印を付け（`- [x]`）、`進捗.md` に書く。画面の「進み具合」は、この印の数で出る。

## 目的

T007 が流し直した 864 run の記録から、**REP006 の事前記録どおりに**、E・P・L と超過の 4 区分を計算し、REP006 の結果・判断・得られた事実・結果から生まれた問い（md）と、報告（tex・PDF）を書く。**事前記録（定義、集計 1〜5、達成条件、起こりうる結果と次の一手、基準）は、結果を見てから動かさない。**

## 進め方の決まり（このタスク固有）

1. **前提：T007 が完了していること。** 最初に `agentctl.py list` で確かめる。T007 が「完了」でない、または 864 run がそろっていないときは、`進捗.md` に書いて止める。
2. 最初に、`経緯.md`、この文書、`.claude/rules/unattended.md`、`CLAUDE.md`、`research/README.md`（特に 6.3、9.）、`research/MASTER.md`、`research/Q001_…/Q001.md`、**`REP006_…/REP006.md` と `REP006.tex`（全部）**、`.claude/rules/hypothesis_and_verification.md`、`.claude/rules/research_conduct.md`、`.claude/commands/make_progress_report.md`、`DB/README.md`、`DB/記録の一覧.md`、`dashboards/agents/tasks/T007/進捗.md` を読む。
3. **使うデータ：** T007 が流した 864 run。DB は、T009 で作り直された新しい構造（Parquet が原本。`DB/README.md` を読む）で、`rep` の名前と `param_id` は、T007 の `進捗.md` に書いてある。記録の段は、detail（全 864 run）と full（8 run）。**`status` = ok、`github_dirty` = false の run だけ**を使う。`DB/_legacy/`（旧 run の退避）は、使わない（記録が足りない）。
4. **解析の定義は、REP006.md の 3 節（セルの区分と記録する量。集計 1〜5）と 3.2（達成の条件）、2 節の式（E・P・L、4 区分）に従う。** 計算は、`research/Q001_…/REP006_…/programs/` に置く（共通で使えるものは `research/src/`）。DB を読むだけで、DB・`github/` に書き込まない。
5. **事前記録に無い量を足したときは、「あとから足した」と明記し、判断には使わない**（REP005.md 5 節の書き方）。集計の列の選び直し（たとえば、平均が発散するので中央値にする）をしたときは、「判断の定義の変更ではない」ことと理由を、REP の md に書く。
6. **判断は、7 節の枝に従う。** 結果が、どの枝に当たるか（手法の群ごと）を、事前の基準（「超過したセルの 50% 以上が 1 つの区分に入る手法は、その型が主」）で決める。**基準は、Claude が置いたもので、ユーザーの確認が済んでいない**（U2）。動かさずに使い、「確認待ちの基準だった」と書く。どの枝にも当たらないとき、または複数に当たるときは、正直に書く。
7. **事実と解釈を分ける。** 結果の節は「〜であった」の事実だけ。解釈は、判断・生まれた問いの節に、「〜と考えられる」で書く（`make_progress_report.md` のルール 0）。「抽選型が主」でも、「その手法の入札が良い」とは書かない（7 節の注）。
8. **報告（tex・PDF）：**
   - 型は探索型。`REP006.tex` の「3 結果」（今は「実験は未実施である。」）を、結果に置き換える。構成は、今の tex（目的、実験、結果）を保つ。**「結果から生まれた問い」は、PDF に書かない**（md にだけ）。サマリーの 3 文目も、結果と判断にする。
   - **式には番号を付け、文中で「式(N)」と言及する。文章は短く、節の粒度を揃える。** 結果は、表と図に寄せる。図は、`fig/` に置き、**2 段組みで文字が読める大きさ**にする（時系列や多数の小図は 2 段抜き `figure*`）。
   - `.claude/commands/make_progress_report.md` の手順でコンパイルし、PDF を画像にして**目で確かめる**（`pdftoppm`。表のはみ出し、図の大きさ）。ページ数は、制限しない（読みやすさを優先）。
9. **REP006.md：** 9 節（結果）、10 節（判断）、11 節（得られた事実）、12 節（結果から生まれた問い）を書く。8 節（実験の記録）に、使った run（`rep` の名前、`github_version`、run の数）、`programs/` のスクリプト、定義の変更の有無を足す。13 節（未確認事項）に、置いた仮定と迷った点を足す。**md の構成の組み替えは、しない**（経緯 5）。冒頭の `status:` と `summary:` を、判断（支持・不支持の代わりに、探索は「達成」「未達成」）に直す。
10. **ほかの文書の更新：** `Q001.md`（子の一覧の REP006 の行、今の状態）、`MASTER.md`（現在地、分かったこと。「判断の履歴」には、方針を変えたときだけ）、`research/flow.md`（`python3 research/src/make_flow.py`）、問いのまとめ PDF（`python3 research/src/build_summary.py Q001`）を直す。
11. **コミット。** 区切りごとに、自分が変えたファイルを名前で指定し、種類で分ける（解析のコード・結果の表と図／REP006 の md・tex・PDF／Q001.md・MASTER.md・flow・まとめ）。`git -c user.name=yayoten -c user.email=g2222077@tcu.ac.jp commit …`。**push はしない**。他の Claude・ユーザーの未コミットの変更（`CLAUDE.md`、`.claude/`、`dashboards/`、`github/Test/README.md` など）に触らない・巻き込まない。1 ファイル 50MB を超えるものを、コミットしない（`results/raw/` は `.gitignore`）。
12. **負荷。** 解析は、DB を読む処理で、重くなりうる（`raw/` の parquet は、864 run で約 10GB）。`free -g` と `uptime` を確かめ、DuckDB のメモリと並列は、空きの範囲に抑える。重い集計は、run ごとに集約してから、まとめる。
