# T003 ルールベース3手法の検証のやり直し（確定した設定で）

> 無人で動く Claude への指示書。起動した Claude は、まず `経緯.md`、次にこの文書と `.claude/rules/unattended.md` を読む。
> 進み具合は、チェックリストに印（`- [x]`）を付け、`進捗.md` に書く。

## 目的

REP003 で確定したベースライン設定（`research/src/baseline_params.json` の `rule_based`。3 手法とも既定値）で、ルールベース 3 手法の検証を行い、**新 REP002（ルールベース手法 3 種の検証）**の報告を作る。
流れは「パラメータを固めた → 固めた設定で実験した」とする。**報告に、「パラメータをどう決めたか」「古い版をやり直した」という経緯は書かない**（決め方は新 REP001 に書いてある）。

## 進め方の決まり（このタスク固有）

1. 最初に `research/README.md`、`research/MASTER.md`、`REP003_…/REP003.md` の 8 節、旧 REP001・旧 REP002 の md、`.claude/rules/` の 2 つ（`research_conduct.md`、`hypothesis_and_verification.md`）、`.claude/commands/make_progress_report.md` を読む。
2. 作業フォルダは `research/W001_既存手法の比較/再実施_ルールベース/`（予約済み）。**番号つきのフォルダは作らない**（番号の入れ替えは T005 が行う）。中に `REP.md`（旧 REP の md と同じ書式。ID の行は「新 REP002」と書く）、`params/`、`programs/`、`results/`、`fig/` を置く。
3. DB の `rep` の値は、既存の `REP001`〜`REP005` と**重ならない名前**にする（例：`REP002new`）。付けた名前を、`REP.md` と `進捗.md` に書く（T005 が対応表に載せる）。`DB/runs` の既存の原本は、消さない・上書きしない。
4. **まず、やり直しが要るかを判定する（下の B）。** 実験の前に、判定の基準を `REP.md` に書いてコミットする。結果を見てから動かさない。
5. 事前記録（目的・達成条件・条件・判定の基準・起こりうる結果と次の一手）を、実験の前に `REP.md` に書いてコミットする（`research/README.md` 9.、`research_conduct.md` 5 節）。
6. 評価は、**評価の日（エピソード 0〜3）・48 位置**。設定は、`baseline_params.json` の `rule_based` を引く（`kwargs` は空 = 既定）。掃引はしない（迷ったら進捗に記録して、しない側に倒す）。
7. サーバーの負荷：評価の並列数は、**このタスクは 3 まで**（T004 と合わせて 6 まで。1 run 約 2.9GB。空き 23GB のため余裕を取った）。流す前に `free -g` と `uptime` を確かめる。T004 が終わっていて、空きが十分なら、7 まで上げてよい（available が 4GB を切りそうなら下げる）。
8. `github/` は、原則触らない。不具合が見つかったら、直さず `進捗.md` に書く（直すなら、`github/Test/` を全件回す。`CLAUDE.md`）。
