# agents/ — エージェントの台帳

| 場所 | 中身 | 作る人 | git |
|---|---|---|---|
| `tasks/T001/task.json` | タスク（予約）1 件。題、概要、状態、予約しているフォルダと番号、Claude の設定（`claude`: model・effort・permission_mode。権限のモードは `auto` を明示する）、動かす端末 | `programs/agentctl.py new` | 管理する |
| `tasks/T001/経緯.md` | **このタスクが、どういう流れでできたか。** 決まっていること、選ばなかった案、未決のこと | 指示を出す側（起動する前に書く） | 管理する |
| `tasks/T001/指示書.md` | 何をやるか。チェックリスト（`- [ ]`）の印の数が、画面の「進み具合」になる | 指示を出す側 | 管理する |
| `tasks/T001/進捗.md` | 何をやったか、今どこか、止まった理由 | 担当の Claude | 管理する |
| `sessions/<ID>.json` | 動いている Claude 1 つ。最後に動いた時刻、編集したファイル、受けた警告 | フック（自動） | 管理しない |

1 件 1 ファイルにしているのは、台帳そのものが取り合いにならないようにするため。
使い方は [../README.md](../README.md)。

## モデルと effort、トークンの節約（ユーザーの決まり、2026-10-11）

エージェントのトークンの消費を抑えるための決まり。**`agentctl.py` は、`--effort` に `low` か `medium` しか受け付けない**（`high` 以上は、予約も起動も、拒否する）。

| 決まり | 内容 |
|---|---|
| **effort** | **medium が上限。`high`・`xhigh`・`max` は使わない。** 既定は medium。どうでもよい・単純な作業は low。**ユーザーに聞かずに、上げない**（2026-10-10 に、T006・T008・T009・T010 を high にして、叱られた） |
| **モデル** | 仕事の種類で分ける。設計・試行錯誤・結果を見て調整する・判断する・報告を書く → **Opus**（medium）。決められた実験を流すだけ・結果の集計だけ → **Sonnet**（low〜medium）。**研究の推論（設計・判断・考察）は、Opus のまま。節約のために手放さない** |
| **実行を待つ間は、AI を動かさない** | 長い実行（数時間）は、AI なしのシェルスクリプトで流し、**終わったら、スクリプトが次のエージェントを `agentctl.py launch` で起動する**。待つ間に、AI が何度も確認すると、会話が積み上がって、トークンを無駄に使う。例：T007（準備と起動）→ スクリプト（864 run を流す）→ T011（照合と REP の仕上げ）→ T008 |
| **会話は、区切りで切る** | 1 つの会話で、「調べる→作る→実行→検証→報告」を全部やらせない。受け渡しは、`進捗.md` と指示書・経緯の md だけにする。次に起動する Claude は、それを読んで、そのとおりに動く |
| **指示書・経緯は、短くしない** | 背景を汲んで、研究を設計するために要る。短くしても、削減の効果は小さく、研究の筋道が失われるほうが大きい。節約は、**会話のターン数を減らす**ことで行う |
| **ほかの節約** | PDF の確認は、`pdftotext` で済ませ、画像にして見るのは最後の 1 回にする。長いログは `head`・`tail`・`grep` で切る。大きいデータは、AI に読ませず、スクリプトで集計する |
| **対話の会話** | 長くなったら、ユーザーが自分でリセットする。状況は、`research/MASTER.md`、各タスクの `進捗.md`、メモリに残る |

## 経緯の書き方（**いちばん大事な決まり**）

研究は、結果だけでなく、**そこに至る筋道**が評価される（`.claude/rules/research_conduct.md`）。考察が中心のタスクほど、
「なぜこのタスクをやるのか、何が決まっていて、何を検討して外したのか」が分からないと、担当の Claude が、
筋道から外れたこと（思いつきの案、決まったことのやり直し）をしてしまう。そのため、**指示書とは別に、経緯を必ず残す。**

- **書く人と時期**：指示を出す側が、**起動する前**に書く。担当の Claude は読むだけ（食い違いに気づいたら `進捗.md` に書く）。
- **強制**：`経緯.md` が、ひな形の「未記入」の行を含んだままだと、`agentctl.py launch` は起動しない。画面のタスク一覧にも、記入状況が出る。
- **このファイルだけで分かるように書く。** 元の会話の記録は 30 日で消える。会話を読まなければ分からない書き方にしない。

### 何を書くか

| 節 | 書くこと | 注意 |
|---|---|---|
| 1. 一言で | このタスクは、何のために、なぜ今あるのか（2〜3 文） | 作業の内容ではなく、理由を書く |
| 2. 決まっていること | ユーザーの決定。日付、決まったこと、**ユーザーの言葉（短く）**、理由 | **担当が変えてはいけないもの。** Claude の提案が通ったものも、通ったと分かる形で書く |
| 3. 流れ（時系列） | 何が問題になり、何を調べ、何が分かり、何を決めたかを、順に。**数字と REP の ID を付ける** | 事実（測ったこと）と、解釈・推測を、文を分けて書く。「〜であった」と「〜と考えた」 |
| 4. 選ばなかった案 | 検討して外した案と、理由、誰が決めたか | 外した理由が消えると、同じ案が何度も出てくる |
| 5. 未決・未確認 | まだ決まっていないこと、確かめていないこと、Claude が置いた仮定 | 仮定は、仮定と分かるように書く。ユーザーの指示と混ぜない |
| 6. 元の会話 | セッション ID と、記録のパス | 参照用。これが無くても分かるように 1〜5 を書く |

### 書き方の決まり

- **誰の言葉かを区別する。** 「ユーザーの決定」「Claude の提案」「Claude の解釈・推測」「測定した事実」を、混ぜない。
- **ユーザーの意図を、作り話で補わない。** 読み取りに自信が無いところは、「（Claude の読み取り。要確認）」と書く。
- **筋道を飛ばさない。** 「A である。B である。だから C と考えた」と書く。結論だけを書かない。
- **うまくいかなかったこと、遠回りも書く。** 後から同じ回り道をしないため。ただし、長くしすぎない（目安は A4 で 2〜3 ページ）。
- 日付は、絶対日付（2026-10-09）で書く。「昨日」「さっき」と書かない。

### 経緯が足りないと思ったら（担当の Claude）

- 経緯と指示書が食い違う、または、経緯に書かれていない大きな判断が要るときは、**進めずに**、`進捗.md` に書いて、できる別の作業を進める（`.claude/rules/unattended.md` の 3 節）。
