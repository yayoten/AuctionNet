# エージェントの管理と、Claude の使用量 要件定義

作成日：2026-10-09　状態：実装済み（1 節の「未確認」を除く）

サーバー負荷の画面（`要件定義_1_サーバー負荷.md`）に、画面を 2 つ足し、Claude を無人で動かす仕組みを加える。

## 1. 目的と背景

| 困っていること | この仕組みでやること |
|---|---|
| MacBook の Wi-Fi が切れると、Claude の作業が止まる | サーバーの tmux の中で Claude を動かす。ssh が切れても動き続ける |
| 途中の承認が手間 | 確認なしで全部実行する設定（`--dangerously-skip-permissions`）で起動する。歯止めは決まりの文書（`.claude/rules/unattended.md`）で掛ける |
| 複数の Claude が、同じ場所を同時に触る | タスクごとに、フォルダと番号を予約する。予約の外を編集しようとした Claude には、警告を出す |
| どの Claude が、どこで、何をしているか分からない | 台帳（`agents/`）に自動で記録し、画面で一覧にする |
| どれだけ使っているか分からない | 会話の記録から、トークンの使用量を集計する |

前提：`/home/yayoten` の外は、絶対に触らない。

**分かっていること**：VSCode（Remote-SSH）の Claude も、tmux の Claude も、実体はこのサーバーで動く。同じフォルダを触るので、衝突するのはこの 2 つである。
自宅の PC など別の端末で動かす Claude は、別の場所のコピーを触るので、git を通してしか衝突しない。

**未確認**：確認なしの設定で初めて起動するとき、同意の画面が 1 度出る可能性がある（出たら、`tmux attach` して同意する）。

## 2. 決めたこと（ユーザーと確認済み）

| 項目 | 決定 |
|---|---|
| 置き場所 | `server_info/` を `dashboards/` に改名。コードは `dashboards/programs/` に全部入れ、画面の HTML はその直下に置く |
| 画面 | HTML ＋ CSS。3 つ：サーバー負荷／AI エージェント／Claude の使用量。上のタブで切り替える |
| 無人の Claude の権限 | 確認なしで全部実行。守ることは md（`.claude/rules/unattended.md`）で管理する |
| 衝突の防ぎ方 | 予約の単位は、フォルダと番号。予約の外を編集しようとしたら**警告だけ**出す（編集は止めない） |
| 台帳の形 | 1 タスク 1 フォルダ、1 セッション 1 ファイル（台帳そのものが取り合いにならないように） |
| 進み具合 | ％の見積もりはしない。指示書のチェックリストの印の数（済んだ数／全体）で出す |

## 3. 機能

### 3.1 AI エージェントの画面（`agents.html`）

| 部分 | 出すもの |
|---|---|
| いまの状態 | 稼働中の Claude の数（端末・画面ごと）、有効なタスクの数、予約されているフォルダと番号の数 |
| 警告 | 直近 24 時間の、予約の外・ホームの外への編集 |
| タスク（予約） | ID、状態（予約／実行中／完了／中止）、題・概要・指示書のパス、動かす端末と画面（tmux の名前と生死）、開始、予約している場所、進み具合 |
| 動いている Claude | 状態（稼働中／待機／終了）、端末・画面、開始、担当のタスク、最初の指示、最近編集したファイル |

- 「動いている Claude」は、フックの記録と会話の記録から自動で出す。人やエージェントの申告に頼らない。
- タスクは `programs/agentctl.py` で作る（`new` / `launch` / `done` / `cancel` / `stop` / `list`）。

### 3.2 フック（`.claude/settings.json` → `programs/agent_hook.py`）

| きっかけ | やること |
|---|---|
| 会話の開始 | 台帳に登録する。環境変数 `AGENT_TASK` があれば、そのタスクに結び付け、状態を「実行中」にする |
| ファイルを編集する直前 | 他のタスクが予約している場所、またはホームの外なら、警告を返す（Claude と画面の両方に出る。編集は止めない） |
| 道具を使ったあと | 最後に動いた時刻と、編集したファイルを記録する |
| 応答の終わり・会話の終わり | 時刻を記録する |

フックは、失敗しても Claude の作業を止めない。

### 3.3 Claude の使用量の画面（`usage.html`）

| 部分 | 出すもの |
|---|---|
| まとめ | 今日／直近 7 日／直近 14 日の、出力トークン・応答の回数・キャッシュの読み出し |
| 日ごとの推移 | 出力、入力（キャッシュ以外）、キャッシュの読み出し、キャッシュへの書き込み。桁が違うので、種類ごとに別のグラフ |
| 時間帯 | 直近 7 日の、時刻ごとの出力トークン |
| 内訳 | モデル別、起動のしかた別、フォルダ別、出力の多い会話の上位 10 |

- もとは、Claude Code が残す会話の記録（`~/.claude/projects/`）。同じ応答が複数行に分かれて記録されるので、応答ごとに 1 回だけ数える。
- 出せないもの：別の端末で動かしたぶん、30 日より前のぶん（記録が消える）、料金、プランの上限に対する残り。

## 4. 非機能

- 依存は、Python 3.10 の標準ライブラリだけ（サーバー負荷の画面と同じ）。
- 研究用の `DB/` には書かない。
- 生成物（3 つの HTML、`history/`、`logs/`、`agents/sessions/`）は git で管理しない。タスク（`agents/tasks/`）は管理する。

## 5. 完成の判定

- `programs/run.sh` を 1 回動かすと、3 つの HTML が作り直される。`serve.py` 経由で、3 つとも開け、「更新」が効く。
- この会話のような、フックを入れたあとの Claude が、画面の「動いている Claude」に、編集したファイルつきで出る。
- 予約したフォルダを、別の Claude が編集しようとすると、警告が出て、画面の上にも出る。
- `agentctl.py launch` で、tmux の中の Claude が指示書を実行し、ssh を切っても動き続ける。

## 6. やらなかったこと・限界

- 予約の外への編集を**止める**ことはしない（ユーザーの判断で、警告だけ）。警告を無視した編集は防げない。
- `Bash` の中でのファイルの書き換え（`sed -i`、`mv` など）は、編集の道具を通らないので、警告も記録も出ない。
- ％の進み具合、通知（メールなど）、使用量の上限での自動停止は、作っていない。
