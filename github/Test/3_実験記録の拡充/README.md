# 3_実験記録の拡充 — 記録を足しても結果が変わらないことと、記録の中身の検証

実験のやり直しを減らすために、実験のたびに残す量を増やした（T006、2026-10-10。記録の形式の版 2）。
`github/`（`BiddingEnv`・`run_test`・各戦略）に記録用の出口を足し、`research/src/run_experiment.py` が表に書く。
ここでは、**記録を足しても結果（購入・支払い・成績）が変わらないこと**と、**記録どうしが整合すること**を pytest で確かめる。
何を、なぜ取るかの一覧は `DB/記録の一覧.md`、表と列の意味は `DB/columns.json`。

## 実行

```bash
cd github/Test/3_実験記録の拡充
../../../.venv/bin/python -m pytest                    # 全部（約 3 分。2026-10-10：49 passed）
../../../.venv/bin/python -m pytest -m "not slow"      # 速いものだけ（環境の乱数の確認など。数秒）
```

`test_05` の相手の run（本番の規模、18 run）は、次で作る（約 15 分。`DB/runs/` に入る）。

```bash
.venv/bin/python research/src/run_experiment.py github/Test/3_実験記録の拡充/params/check_same_as_old_v2.json --workers 4
```

## 分かったこと（2026-10-10、Linux x86_64 / Python 3.9.16 / numpy 1.24.2）

これまで「コードを読んだだけ」だったこと（REP006.md の C3・C5・C6）を、実行して確かめた結果である（test_02）。

| 番号 | 確かめたこと | テスト |
|---|---|---|
| C3 | 雑音（標準化したもの）は、広告主ごとに、下側 −2×u1、上側 +2×u2 で打ち切られる。u1・u2 は、広告主 × エピソードで決まる 0〜1 の乱数で、上下で対称でない。雑音の平均は、打ち切り正規分布の平均に一致し、広告主によって、正にも負にも偏る | `test_c3_*` |
| C5 | 予算超過の取り消しは、超過した広告主の、枠ごとの落札のうち ceil(数 × 超過率) 件の入札を 0 にする。選び方は、毎回、種 1 の乱数。ほかの広告主の入札は変えない | `test_c5_*` |
| C6（雑音） | 標準化した雑音は、**（そのティックの中での機会の番号、広告主）だけで決まる。** ティックが違っても、そのティックの機会の数が違っても、同じ番号の機会には同じ雑音が当たる。エピソードが違っても、もとの一様乱数は同じで、打ち切りの幅（u1・u2）だけが変わる | `test_c6_same_noise_*`、`test_c6_the_underlying_uniform_*` |
| C6（抽選） | 購入の抽選も、同じ種で作り直される。確率が同じ並びなら、同じ結果になる。確率が 0 の機会は乱数を使わないので、そこから先は、乱数の当たり方がずれる（先頭に 1 つ入るだけで、独立な抽選と同じ程度まで一致が崩れる）。推定価値が 0 の機会（σ も 0）がこれに当たる | `test_c6_conversion_draw_*` |
| C6（露出） | 露出の抽選も、枠の並びが同じなら同じ結果。枠 3 は、抽選そのものは 0.6 だが、同じ機会の枠 2 が露出しないと取り消されるので、露出率は約 0.48（0.8 × 0.6） | `test_c6_exposure_rates_and_slot3_rule` |

- 上は、関数を直接呼んで確かめたものである。**本番の run で、これが成績にどう効くか（たとえば、L の標準偏差が T2 の予測より大きくなるか）は、確かめていない**（REP006 の集計5 で見る）。

## 本番の規模での照合（2026-10-10、`github/` の版 92b564e）

`params/check_same_as_old_v2.json` の 18 run（ルールベース 3 手法 × 6 位置 × エピソード 0〜3、PV 数 50 万、記録の段 standard）を、4 並列で流した（572 秒）。

| 比べたもの | 結果 |
|---|---|
| 相手 | 再実施（T003）の `check_same_as_old` と `repro_pid_p0` の 18 run（記録の形式の版 1、`github/` の版 5c8436a80a、同じ端末） |
| `episodes`（13 列 × 72 セル） | 全部一致（丸めの差も無い） |
| `ticks`（15 列 × 3,456 行） | 全部一致 |
| `agents`（4 列 × 3,456 行。背景の 47 社を含む） | 全部一致 |
| ティックの合計とエピソードの値 | 支払いの相対差の最大 4e-16、購入・N_est・N_real の差 0（`DB/query.py`） |
| 恒等式 R = E × P × L | 72 セル（購入 1 以上）で、対数の差の最大 0 |

`test_05_same_as_old_runs.py` は 4 passed。**学習ベース 5 手法は、本番の規模では照合していない**（縮小設定の IQL だけ。流し直しのときに確かめる）。
