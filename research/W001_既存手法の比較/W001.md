# W001 既存手法の比較

## 位置づけ

問いを立てられるだけの情報がまだない段階の作業。最終的には新しい入札方法を提案したいが、そのためには既存手法を動かして、次のことを知る必要がある。

- このシミュレータで既存手法を動かすと、どれだけの時間・メモリがかかるか（研究の規模感）。
- 論文に書かれた手法間の傾向（Online LP が最良、など）が、手元の環境で再現するか。
- 後の考察で必要になりそうな特徴量を、あらかじめ取っておく。

問いが立ったら、この作業の中身を問い（Q）の下に移す。IDは変えない（`research/README.md` 4. IDの付け方）。

## 目的の変更（2026-10-08）

**「論文の結果を再現する」ことは目的にしない。以後の作業のベースラインになる、既存手法のパラメータ設定を決める。**

- 理由：REP001・REP002 で、手法間の倍率と一部の順位が論文と合わなかった。論文には細かいパラメータが無く、公開コードも論文の実験と同じ版とは限らない（既定の学習ステップ数が 100 の手法がある、など）。数値を合わせる作業には終わりが無い。
- 以後の比較は、この環境の中での相対評価で行う。そのために、全手法を公平に動かせる設定を決める（REP003）。
- 上の「位置づけ」の 2 つ目（論文の傾向が再現するか）は、参考として記録するだけにする。

## 作業の範囲（2026-10-07 に決めた）

- 対象：ルールベース3手法（PID / ABid / OnlineLP）。学習ベース（BC / IQL / CQL / BCQ / TD3_BC / DT）は、約80GBの学習データが手元にないので、この作業では扱わない。次のREPで扱うかどうかは別に決める。
- （2026-10-08 追加）学習ベース 5 手法（BC / IQL / CQL / BCQ / TD3_BC）を、公開データ（約77GB）を取得して学習し直し、ベースラインを作る（REP002）。DT はシミュレータ側に戦略が無く、MOPO・COMBO は学習コードが無いので、対象外。
- （2026-10-08）手法どうしを比べる run は、同じ端末で流す。Windows と Linux で、結果が一致しないセルがあった（REP002）。
- 最適化：各手法の主要パラメータを少数ずつ振る。本格的な探索（グリッド／ベイズ最適化）はしない。
- 実験結果は、リポジトリ直下の `DB/` に溜める。REPごとに結果を別々に持たず、後のREPが過去の結果をそのまま引けるようにする（`DB/README.md`）。
- パラメータは `params/*.json`（このフォルダの各REP内）から流し込む。コードに直書きだった値は、引数にして json から変えられるようにした（`github/` の変更はコミットメッセージに理由を書いてある）。
