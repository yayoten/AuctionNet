## 4. 材料から考えたこと

### 4.1 筋道

1. M1・M2 から、PID と ABid は、多くのセルで実績 CPA が制約を超える。超過率の中央値は +0.24〜+0.51 である。
2. C3 から、実績 CPA が決まるまでに、買う段（E）、推定と実際の確率のずれ（P）、抽選（L）の 3 段がある。
3. **E で超えうる材料がある。** M3 から、ABid の α（約 115）は、C（60〜130）がそれより小さい位置では、C を上回る（そういう位置がいくつあるかは、数えていない）。C2 から、α が C を上回る時間帯があれば、E は 1 を超えうる。
4. **L で超えうる材料もある。** M4 と T2 から、購入数が数十件なら、抽選だけで実績 CPA は 2 割ほど動く。M2 の超過率と同じ桁である。
5. **P で超えうる材料もある。** C4 から、雑音の打ち切りは上下で対称でないので、推定価値は、広告主 × エピソードごとに、実際の確率から一方向にずれる。
6. したがって、手元の材料だけでは、超過がどの段で生じているかを決められない。3 つの説明は、同じ「実績 CPA ÷ 制約」に対して、E・P・L の値の出方が違う。そこを測れば、区別できる。

### 4.2 仮説（1 つ）

| 項目 | 内容 |
|---|---|
| 現象 | ペナルティを受けるセルが多い（M1） |
| 仮説（買い方説） | 超過は、抽選より前の、買う段で生じている。α が C を上回る時間帯に、「支払い ÷ 推定価値」が C を超える機会を買い、それが 1 日の平均を C より上に引き上げる |
| 正しければ見えるはずのもの | ペナルティを受けたセルの大半で、E が 1 を超える。セルごとに log(実績 CPA ÷ C) を log E に対して描くと、傾き 1・切片 0 の線のまわりに並ぶ。線からのずれ（log P + log L）は、0 を中心に散らばり、期待購入数が大きいセルほど小さい |
| 捨てる基準 | 5.4 |
| 最終の成果 | 手法ごとの score と、ペナルティを受けたセルの割合を報告する。判断には使わない |

- この仮説を主に置いた理由：3 つのうち、手法の違い（M1 の PID・ABid と OnlineLP の差）を説明できるのは、買い方説だけである。P と L は、手法が同じ機会を買うなら、手法に依らない。
- ただし、M1 の手法の差は、L でも生じうる（OnlineLP は消化率が低く、期待 CPA が制約より十分に下にあれば、同じぶれでも超えにくい）。だから、M1 だけでは買い方説を支持できない。

### 4.3 対立仮説と、区別する観測

見る量は、ペナルティを受けたセルでの、E・P・L の値である。

| | 買い方説 | 抽選説 | 予測の外れ説 |
|---|---|---|---|
| 仕組み | α が C を上回る時間帯に、割高に買う | 期待値では制約内に買っているが、購入数が少ないので、抽選のぶれで超える | 推定価値が、実際の確率より系統的に高い（C4）。推定では制約内でも、実際の期待購入数が足りない |
| E | 大半で 1 を超える | 1 以下のセルが多い | 1 以下のセルが多い |
| P | 1 のまわり | 1 のまわり | 1 を超える |
| L | 1 のまわりに散らばる | 1 を超える。超過の大きさは、log L で説明される | 1 のまわりに散らばる |
| セルの偏り | α が C を上回る手法・位置に偏る | 期待購入数の小さいセルに偏る | 手法に依らず、同じ位置 × エピソードに偏る |

## 5. 確かめ方

### 5.1 測る量

1 セル（手法 × 位置 × エピソード）について、次を記録する。

| 記号 | 量 | 今の DB |
|---|---|---|
| Cost | 支払いの合計 | ある（`episodes.all_cost`） |
| Conv | 実際の購入数 | ある（`episodes.reward`） |
| N_est | 露出した機会の、推定価値の和 | **無い** |
| N_real | 露出した機会の、雑音を加えたあとの確率（0〜1 に切ったもの）の和 | **無い** |
| S_over | α が C を上回ったティックでの支払い ÷ 全支払い | 今の DB から計算できる（`ticks.alpha_eff`、`ticks.cost`） |

```
E = Cost ÷ (N_est × C)      P = N_est ÷ N_real      L = N_real ÷ Conv
E × P × L = 実績 CPA ÷ C     （定義から必ず成り立つ）
```

### 5.2 実験の条件（案）

| 項目 | 内容 |
|---|---|
| 変えるもの | 手法（8 手法。REP002 と同じ重み・同じ設定） |
| 固定するもの | 環境（`test.gin` の既定）、48 位置 × エピソード 0〜3、`seed=1`、端末（REP002 と同じ） |
| `github/` の変更 | N_est と N_real の記録を足す。入札・落札・抽選の計算は変えない |
| 流す量 | 8 手法 × 48 位置 = 384 run（記録が無いので、REP002 の run は使えない） |

| 番号 | 確かめること | 通らないとき |
|---|---|---|
| K1 | 記録を足す前後で、`episodes` の全列が一致する（回帰テスト） | 記録の足し方を直す。実験に進まない |
| K2 | 全セルで、E × P × L が 実績 CPA ÷ C に一致する | 分解の定義を見直す（予算を超えたときの落札の取り消しが、記録に入っていない可能性） |

### 5.4 捨てる基準（案。数値はユーザーと決める）

手法ごとに、ペナルティを受けたセルのうち、E が 1 を超えるセルの割合 r を見る。

| r | 判断 |
|---|---|
| 0.8 以上 | 買い方説を支持（その手法について） |
| 0.5 以下 | 買い方説を捨てる。E が 1 以下のセルを、P と L のどちらが 1 を超えているかで、抽選説・予測の外れ説に分ける |
| その間 | 判断不能（段が混ざっている） |

- 購入数が 0 のセルは、実績 CPA が定義できないので、除いて数を報告する。
- ペナルティを受けたセルが少ない手法（目安は 20 セル未満）は、判断を付けない。
