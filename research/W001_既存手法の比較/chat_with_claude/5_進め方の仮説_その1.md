## 4. 現象と、分解（測定）

### 4.1 現象（観測した事実）

- 既定設定、48 位置 × エピソード 0〜3 で、CPA 超過のペナルティを受けたセルは、PID 82%、ABid 85%、OnlineLP 39% であった（REP001）。
- 予算消化率は、PID 0.99、ABid 0.93、OnlineLP 0.75 であった（REP001）。

### 4.2 コードを読んで分かっている事実（仮説ではない）

- PID は、入札の計算に CPA 制約を使わない。ABid は使う。OnlineLP は、α の上限（制約 × 1.5）として使う。学習ベースは、状態にも報酬にも持たない。
- 入札額は α × 推定価値で、落札したら次点の入札額を払う。したがって、ある機会を落札したときの「支払い ÷ 推定価値」は、そのときの α 以下である。
- 環境は、購入を 3 段で決める（`BiddingEnv.py`）。
  1. 推定価値（`pValue`）が、手法に渡される。
  2. 推定価値に、不確実性（`pValueSigma`）ぶんの雑音を加えた値を、実際の購入確率とする。
  3. 露出した機会について、その確率で購入を抽選する。

### 4.3 分解（定義から必ず成り立つ。測定であって、仮説ではない）

1 つのセル（手法 × 位置 × エピソード）について、

```
実績 CPA ÷ 制約
  = （支払い ÷ 推定での期待購入数）÷ 制約      … 買い方の因子 E
  × （推定での期待購入数 ÷ 実際の確率での期待購入数）  … 予測の外れの因子 P
  × （実際の確率での期待購入数 ÷ 実際の購入数）       … 抽選の因子 L
```

- **E**：手法が、推定価値で見て、どれだけ割高に買ったか。手法の作りで決まる。
- **P**：推定価値が、実際の確率からどれだけずれていたか。環境の雑音で決まる。
- **L**：抽選で、たまたま購入が少なかった（多かった）か。運で決まる。
- 3 つを掛けると、必ず「実績 CPA ÷ 制約」になる。対数をとれば、足し算になる。
- **この分解は、「どの因子が大きいか」を量る道具である。** 仮説は、各因子がなぜその大きさになるかについて立てる（5 節）。

### 4.4 今の DB で測れるもの、測れないもの

| 量 | 今の DB | 対応 |
|---|---|---|
| ティックごとの α（`alpha_eff`）、支払い、落札数、露出数、購入数、残り予算 | ある | — |
| 推定での期待購入数（露出した機会の `pValue` の和） | **無い** | 記録を足して、流し直す |
| 実際の確率での期待購入数（雑音を加えたあとの値の和） | **無い** | 同上 |
| 落札した機会ごとの「支払い ÷ 推定価値」の分布 | **無い** | 要約（分位点など）を記録に足す |

- E、P、L を分けるには、記録を足す必要がある。足すのは記録だけで、入札や抽選の計算は変えない。
- α の時間変化と、制約との大小は、今の DB で見られる。

## 5. 仮説

各仮説を、`.claude/rules/hypothesis_and_verification.md` の枠で書く。
**最終の成果（score、超過率）は、どの仮説でも報告するが、判断には使わない。**

### H1 抽選の因子 L のぶれは、期待購入数だけで決まり、手法に依らない

| 項目 | 内容 |
|---|---|
| 現象 | 実績 CPA が、制約を超えるセルが多い（4.1） |
| 仮説 | 購入は、機会ごとに独立な抽選で決まる。だから、L のぶれの大きさは、期待購入数 N の平方根に反比例し、どの手法でも同じ曲線に乗る |
| 正しければ見えるはずのもの | セルごとの log L の散らばりを、N に対して描くと、1/√N の曲線に沿う。手法で色分けしても、曲線は分かれない。L の中央値は、ほぼ 1 |
| 対立仮説なら、どう見えるか | 「運は無視できる」なら、L はどのセルでもほぼ 1。「抽選が独立でない」（乱数の作りによる偏り）なら、散らばりが 1/√N より大きい、または特定のティック・位置に偏る。「手法が運を左右する」なら、手法ごとに曲線が分かれる |
| 捨てる基準 | 散らばりが 1/√N から系統的に外れる。または、手法ごとに分かれる |
| 最終の成果 | 「期待値では制約内なのに、実績で超えた」セルの割合を報告する。判断には使わない |

- 補足：乱数は、`BiddingEnv` の中で、固定の種から毎回作り直されているように読める（未検証）。もしそうなら、抽選はティックや手法の間で独立でない可能性があり、H1 は外れうる。外れた場合、それ自体が、このベンチマークについての発見になる。

### H2 買い方の因子 E は、「α が制約を超えていた時間帯の支出の割合」で決まる

| 項目 | 内容 |
|---|---|
| 現象 | PID と ABid は、OnlineLP より、ペナルティを受けるセルが多い（4.1） |
| 仮説 | 落札した機会の「支払い ÷ 推定価値」は α 以下である（4.2）。だから、E が 1 を超えるのは、α が制約 C を超えている時間帯に、まとまった額を買ったときに限られる |
| 正しければ見えるはずのもの | セルごとに、「α > C のティックでの支出 ÷ 全支出」を計算すると、E と単調な関係になる。この割合が 0 のセルでは、E は 1 以下。関係は、手法をまたいで 1 本の線に乗る |
| 対立仮説なら、どう見えるか | 「E は、落札の質（どの機会を選ぶか）で決まる」なら、同じ割合でも、手法ごとに E が違う（線が分かれる）。「E は、相手の入札の高さで決まる」なら、α が C 以下でも、相手が強い位置・時間帯で E が高い |
| 捨てる基準 | 割合と E に関係が無い。または、割合が 0 なのに E が 1 を大きく超えるセルが、相当数ある |
| 最終の成果 | 手法ごとの E の中央値を報告する。判断には使わない |

- ABid は、入札額が「α × 価値²」なので、価値が平均より高い機会では、実質の α が C を超える（コードの事実）。H2 が正しければ、ABid の E は、価値の高い機会への支出の割合で説明できるはずである。

### H3 PID の α が制約を超えるのは、予算の消化の遅れを取り戻す規則が働くからである

| 項目 | 内容 |
|---|---|
| 現象 | PID の予算消化率は 0.99 で、ペナルティを受けるセルが 82%（4.1） |
| 仮説 | PID は、消化が遅れていると判定すると、α を 1.2 倍にする。制約を見ないので、消化が追いつくまで上げ続け、C を超える。超えた時刻は、「遅れている」の判定が続いた直後に来る |
| 正しければ見えるはずのもの | α が初めて C を超えるティックの直前に、「遅れている」の判定が連続している。予算が、その位置の広告機会の量に対して大きい位置ほど、C を超える時刻が早く、超えている時間が長い |
| 対立仮説なら、どう見えるか | 「最初の α（15）が低すぎて、後半に無理に買う」なら、C を超えるのは終盤に集中し、最初の α を上げると、超える時刻が遅くなる。「相手の予算切れで、市場価格が下がる」なら、α が C を超えても、払う額は上がらない（E は上がらない） |
| 捨てる基準 | α が C を超える時刻と、「遅れている」の判定の連続に、関係が無い |
| 最終の成果 | PID のペナルティを受けたセルの割合を報告する。判断には使わない |

- H3 は、PID についての仮説である。OnlineLP・学習ベースには、別の仮説が要る（REP002 のあとに立てる）。

### H4 得になる「余裕」の大きさは、期待購入数 N で決まり、N が大きいほど 0 に近づく

| 項目 | 内容 |
|---|---|
| 現象 | ペナルティは、実績 CPA が制約を超えたときだけ掛かる。下回っても、得は無い（score の定義） |
| 仮説 | 損だけがある形なので、期待 CPA を制約より少し手前に置くのが得になる。どれだけ手前かは、L のぶれの大きさ、つまり N で決まる |
| 正しければ見えるはずのもの | 狙う水準（期待 CPA ÷ 制約）を少しずつ変えて、期待スコアが最大になる点を、位置ごとに求める。その点は、N が小さい位置ほど 1 から離れ、N が大きい位置ほど 1 に近づく。関係は、H1 のぶれの式から計算した曲線に沿う |
| 対立仮説なら、どう見えるか | 「余裕は、N ではなく、予測の外れ P で決まる」なら、最大の点は `pValueSigma` の大きい位置で 1 から離れ、N とは関係しない。「余裕は要らない」なら、最大の点は、どの位置でも 1 |
| 捨てる基準 | 最大の点と N に、関係が無い |
| 最終の成果 | 余裕を取ったときの score を報告する。判断には使わない |

- H4 は、H1 が支持されたあとに進む。H1 が外れたら、H4 の式も変わる。
- H4 は、手法の提案につながる。ただし、検証するのは「最大の点が N とどう関係するか」という形であって、「余裕を取ると score が上がるか」ではない。

### 仮説どうしの関係

```
現象：実績 CPA が制約を超える
 ├─ 分解（測定）：E × P × L
 │    ├─ L はなぜその大きさか ……… H1
 │    ├─ E はなぜその大きさか ……… H2 → （PID について）H3
 │    └─ P はなぜその大きさか ……… 環境の雑音の設定で決まる（仮説は立てていない）
 └─ では、どこを狙うべきか ………… H4（H1 の上に立つ）
```

## 6. 話の運び

| 段 | 内容 | 種類 |
|---|---|---|
| 1 | 既存手法の多くは、CPA 制約を超える | 観測 |
| 2 | 超過を、E・P・L に分けて量る | 測定 |
| 3 | L のぶれは、N だけで決まる | 検証（H1） |
| 4 | E は、α が制約を超えた時間帯の支出で決まる | 検証（H2） |
| 5 | PID の α が制約を超える経路 | 検証（H3） |
| 6 | 得になる余裕は、N で決まる | 検証（H4） |
| 7 | 余裕を、N から決める入札の修正 | 提案 |
| 8 | 相手が変わったとき、E と余裕はどうなるか | 後半の柱（教授のアドバイス） |

- 1〜5 だけで、「現象 → 仕組み → 検証」になる。6〜7 は、その上に立つ。
- 仮説が外れたときに書けること：
  - H1 が外れる → 「このベンチマークの抽選は、独立でない」。評価の信頼性についての発見になる。
  - H2 が外れる → 「E は、α の水準ではなく、機会の選び方で決まる」。次の仮説の方向が決まる。
  - H4 が外れる → 「余裕は、N では決まらない」。P の側を調べる。

## 7. 避ける筋

| 避けること | 理由 |
|---|---|
| 「CPA を明示的に入れる手法」を、新しさとして出す | GRM、C2 が先にある（U1、U5）。構造自体も既知（U2） |
| score で最新手法に勝つことを、目標にする | 比べる相手の再現だけで、時間が尽きる（U9） |
| 検証を「上限を足したら超過が減った」で済ませる | どの仮説でも起きる。仕組みを確かめたことにならない |
| PID だけを相手に、「制約を見ないから悪い」と言う | 言い換えであり、当たり前と言われる。制約を見る手法（OnlineLP、できれば GRM に近い制御）を、必ず横に置く |

## 8. 引用の組み立て

「先行研究の問題点は、自分で見つけたことにする」という前提では、組んでいない。問題の指摘は GRM に明記されていて、同じベンチマークを使う審査者は知っている可能性が高い。伏せると、見つかったときに研究全体の信用を失う。

問題の指摘を引用し、その先を自分の貢献にする。

| 段落 | 書くこと | 引用 |
|---|---|---|
| 背景 | CPA 制約の超過が、成績を大きく下げる | AuctionNet [No0] |
| 既知 | 制約を報酬に混ぜる手法は、違反を診断できない。明示的に制御すると良くなる | GRM [No15] |
| 既知 | 違反は、予測の外れから生じる | GRM [No15]、RoS の不確かさ [2509.16324] |
| 残っている問い | 既存手法の超過は、どの因子がどれだけか。予測が正確でも残る超過は、どれだけか。どういうときに破るか | GRM の違反率の記述、OIL の限界の記述 [2412.11434] |
| 本研究 | 超過を因子に分けて量り、各因子の仕組みを確かめる | — |

- 引用は 5 本前後で足りる。
- GRM が「違反は診断できない」と書いているので、「だから診断する」と言える。伏せるより、主張が強くなる。

## 10. 限界と未確認の点
