# claudeの回答1

## 1. アドバイスの整理

アドバイスは、3 つの主張に分けられる。

| 番号 | 主張 | 種類 |
|---|---|---|
| A1 | 手法の成績は、相手の手法で変わる。だから、どの相手にも勝つ「最強」は無い | 問題の性質についての主張 |
| A2 | 最初の研究目標は、既存手法の振る舞いを「どういうときに、なぜ」まで説明することに置く | 目標の置き方 |
| A3 | 新しい手法は、A2 の途中で気づきがあったときに考える。最初から目的にしない | 順序 |

- A1 は、この環境で確かめられる主張である（相手を変えて、成績が変わるかを見ればよい）。まだ確かめていない。
- A2 と A3 は、研究の進め方の方針である。実験で確かめるものではなく、ユーザーが採るかどうかを決めるもの。

## 2. 「最強のアルゴリズムは無い」を、この環境に当てはめる

### コードで確かめてあること

- 評価は、48 社のうち 1 社（プレイヤー）を試したい手法に差し替え、その 1 社の score を測る形である。
- 残り 47 社の手法は、位置で固定されている（`Controller.initialize_agents`）。内訳は OnlineLP 12、PID 6、IQL 6、TD3_BC 6、MOPO 6、CQL 3、BC 3、BCQ 3、COMBO 3（`1_既存手法.md` の 12 節）。
- この内訳はコードに直書きで、`params.json` からは変えられない。

### そこから言えること

- REP001 の「Online LP > ABid > PID」は、**上の 47 社が相手のとき**の順位である。
- 相手の構成を変えたときに、この順位が保たれるかは、確かめていない。

### なぜ相手で成績が変わりうるのか（説明用の例。確かめていない）

`1_既存手法.md` の 3 節の「おもちゃの 1 ティック」を使う。数字は説明用の仮の数字。

- 落札に必要な額 m は、ライバルの入札で決まる。
- OnlineLP は、残り予算 0.09 のとき α = 56 を引き、お得な PV1 と PV5 を落札した（払う額 0.065、期待購入数 0.0015）。
- ここで、ライバルも同じように「お得な PV」を狙う手法に変わり、PV5 の m が 0.050 から 0.070 に上がったとする。

| | PV5 の m | α = 56 での PV5 の入札額 | PV5 | 落札 | 期待購入数 |
|---|---|---|---|---|---|
| 元の相手 | 0.050 | 0.0672 | 落札 | PV1, PV5 | 0.0015 |
| 相手が同じ PV を狙う | 0.070 | 0.0672 | 落札できない | PV1 のみ | 0.0003 |

- 早見表は過去の記録なので、α は 56 のままである。相手が変わっただけで、期待購入数が 5 分の 1 になる。
- つまり、「お得な PV」は、みんなが狙うとお得でなくなる。これが A1 の言う構造だと、Claude は解釈している。
- 実際のシミュレータでこの現象がどの程度起きるかは、分からない。4 節の「相手側の条件」を変える実験で確かめられる。

## 3. 研究目標の置き方

`MASTER.md` の今の記述と、アドバイスを並べる。

| | 内容 |
|---|---|
| 今の `MASTER.md`（暫定の方向） | AuctionNet を題材に、問題→仮説→検証の形を踏んだうえで、新しい入札方法を提案する |
| アドバイス（A2, A3） | まず、既存手法の振る舞いを「どういうときに、なぜ」まで説明する。新しい手法は、気づきがあれば考える |

- 「問題→仮説→検証の形を踏む」は、アドバイスと同じ向きである。
- 違うのは、「新しい入札方法を提案する」を最初からゴールに置いている点。

**`MASTER.md` の書き換え案（Claude の提案。反映していない）**

- 暫定の方向：AuctionNet の既存の入札手法について、「どの特徴を持つ手法が、どの条件で、どう振る舞い、なぜそうなるか」を、検証を積み上げて説明する。その過程で、説明から導ける改善が見つかったときに、新しい入札方法を提案する。
- 判断の履歴に足す行：2026-10-08、教授のアドバイスを受けて、新手法の提案を最初の目的から外した。

`MASTER.md` は人が書く文書で、最終ゴールは研究の中心なので、Claude は書き換えていない。

## 4. 実験の組み方への影響

### 4.1 測るものが変わる

| | これまで | これから |
|---|---|---|
| 主に見る量 | 手法ごとの score の合計と順位 | 手法ごとの振る舞い（α、落札、支払い、CPA の時間変化）と、それが起きる条件 |
| 結論の形 | 「A は B の 1.5 倍」 | 「A は、条件 X のとき、Y という理由で Z になる」 |
| 条件 | 既定の 1 通り | 条件を変えて、振る舞いが変わる境目を探す |

score の順位は捨てない。「どの条件での順位か」を必ず付けて書く。

### 4.2 説明を 3 段に分ける

「深く踏み込んだ説明」を、実験として扱える形にすると、次の 3 段になる。

| 段 | 問い | REP の型 | 例（REP001 の PID） |
|---|---|---|---|
| 1 何が起きたか | 観測 | 探索 | 序盤に落札がなく、落札が立ち上がるのはティック 7 ごろ以降であった |
| 2 どの条件で起きるか | 条件の特定 | 探索または検証 | 予算・CPA 制約・カテゴリ・相手によって、立ち上がりの時刻は変わるか |
| 3 なぜ起きるか | 原因の検証 | 検証（1 仮説） | 「最初の α（15）が相手の中央値（68）より低いことが原因」を、最初の α だけを変えて確かめる |

- 段 3 は、原因と考えるものを**直接変える**実験にする（`research/README.md` の 2 の 1）。成績が上がったことだけでは、原因の説明が正しいとは言えない。
- 段 1 で止めず、段 3 まで進めたものが、アドバイスの言う「このときに、こうなってしまう」の説明になる。

### 4.3 変える条件の軸

| 軸 | 中身 | 今の状態 |
|---|---|---|
| 自分側 | 予算、CPA 制約、カテゴリ（= 位置） | 48 位置すべてで測ってある（REP001）。位置ごとの分解はしていない |
| 手法の設定 | 各手法のパラメータ | ルールベースは 1 つずつ振ってある（REP001 の E5） |
| 環境側 | PV 数、時間帯ごとの PV の量、エピソード | エピソード 0〜3 のみ。PV 数は 50 万で固定 |
| 相手側 | 47 社の手法の構成 | **固定。コードに直書きで、変えられない** |

- A1（相手で成績が変わる）を確かめるには、相手側の軸が要る。
- 相手側を変えるには、`Controller.initialize_agents` の構成を引数に出す変更が要る（`github/` の変更。既定値は今のままにし、回帰テストを足す）。

### 4.4 手法ごとに「特徴の表」を作る

既存手法を一通り試した結果を、手法ごとに同じ形で溜める。項目の案：

| 項目 | 中身 |
|---|---|
| 何を見て α を決めるか | 予算、CPA 制約、履歴（`1_既存手法.md` の 2 節の表） |
| 観測した振る舞い | REP の ID つきの事実 |
| 良い条件・悪い条件 | 位置、相手、時間帯 |
| なぜそうなるか | 仮説か、検証済みかを明記 |
| まだ分からないこと | 次の REP の候補 |

置き場所と書式は決めていない。`W001.md` に足す、または別のファイルにする、のどちらもありうる。

## 6. 次の一手の候補

いずれも Claude の提案で、決定ではない。

| 候補 | 内容 | 新しい実験 | `github/` の変更 |
|---|---|---|---|
| N1 | REP002 を終える（8 手法のベースライン） | 要る（計画済み） | 済み |
| N2 | 既にある結果の分解。手法間の差を、ペナルティ前の報酬とペナルティのどちらが説明するか（REP001 で生まれた問い）。あわせて、位置（予算・CPA 制約・カテゴリ）ごとに振る舞いを分ける | 要らない | 要らない |
| N3 | 手法ごとの「なぜ」の検証。1 REP に 1 仮説。例：PID の序盤の遅れは最初の α が原因か、ABid の成績は予算切れの早さが原因か | 一部要る | 場合による |
| N4 | 相手の構成を変える実験。例：プレイヤーと同じ手法の社数を増やすと、プレイヤーの成績は下がるか | 要る | 要る（構成を引数に出す） |

**推奨の順：N1 → N2 → N3 → N4。**

- N1 を先にする理由：「一通り試す」が終わらないと、手法の特徴を並べられない。計画も道具もできている。
- N2 を次にする理由：新しい実験なしで、段 1 と段 2 が進む。N3 の仮説を選ぶ材料にもなる。
- N4 を最後にする理由：アドバイスの中心（A1）に最も近いが、コードの変更が要り、条件の数が多い。先に各手法の振る舞いが分かっていないと、何を変えるかを決められない。
- N4 を早めたい場合は、N2 のあとに、条件を 1 つに絞った小さい探索として入れられる。

問いの立て方：N2 以降は、問いが 1 文で書けるようになる。その時点で、W001 から Q（大きな問い）を立てる候補になる。例：「既存手法の成績の差は、何によって決まるか」。これも決めていない。
