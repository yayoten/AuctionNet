# REP002 学習ベース手法5種の動作検証

親：W001（作業。問いは未確定）　型：探索　日付：2026-10-08　状態：達成

## 1. 確認したい現象（仮説は立てない）

既存の学習ベース入札手法が、このシミュレータでどう動くかを知り、ルールベース（REP001）と並べた**ベースライン**を作る。
REP001 では、約80GBの学習データが手元になく、学習ベース手法を扱えなかった。今回は公開データを取得して、学習からやり直す。
手法ごとの成績を事前に予想できる材料がないので（学習ベースを自分で学習して評価したことがない）、探索にする。

知りたいこと（番号は、下の達成条件と結果の対応に使う）。

- L1 データ。公開データ（21 日分）を欠けなく取得でき、学習データ（1 行 = 広告主 1 社 × 1 ティック）を作れるか。
- L2 学習。5 手法を、本家の既定設定のまま学習できるか。どれだけ時間がかかるか。同じ条件で同じ重みになるか。
- L3 評価。学習した重みを、48 社のどの位置に置いても、最後まで走るか。
- L4 ベースライン。8 手法（ルールベース 3 ＋ 学習ベース 5）を同じ端末・同じコードで並べると、成績はどう並ぶか。
- L5 学習の条件への感度。学習ステップ数、乱数シード、重みの出どころ（自前／同梱）で、成績はどれだけ動くか。
- L6 特徴量。後の考察に使う量を、欠損なく取れているか。

## 2. 達成とみなす条件（実験の前に決める）

次をすべて満たしたとき「達成」とする。

| 番号 | 条件 |
|---|---|
| L1 | `Test/2_学習データと学習手法/` の test_01・test_02 が全件通る（21 日分、欠損なし、48 社 × 約 50 万 PV、学習データ 21 × 48 × 48 行） |
| L2 | この REP の全モデルが status=ok で、損失が最後まで有限である。既定設定の 5 モデルは、学習し直すと重みの SHA-1 が一致する（test_05） |
| L3 | この REP の全 run が status=ok で、score が有限である |
| L4 | 8 手法の、192 セル（48 位置 × エピソード 0〜3）の score 合計・ABid を 1.0 とした値・順位が記録されている（判断は付けない） |
| L5 | 下の 3 つの追加条件の成績と、既定設定に対する比が記録されている（判断は付けない） |
| L6 | この REP の run の `episodes`・`ticks`・`agents` の全数値列に、NaN・無限大がない |

**L4 の集計の定義。** 手法ごとに、既定設定（学習ベースは「本家の既定のステップ数・seed=1 で自前学習した重み」）の run を、48 位置 × エピソード 0〜3 に置く。
各セルの `score_component`（CPA 超過ペナルティ込み）を手法別に合計する。あわせて、REP001 と同じ量（ペナルティ前の平均報酬、ペナルティが掛かったセルの割合、
CPA 超過率の中央値、予算消化率、順位の中央値）を記録する。論文の図10（目視の概算：Online LP 6.5〜7、DT 4.5、IQL 2.6〜3、PID 2.3〜3.5、BC 2.3〜2.5、Abid 0.4〜1）とは、
同じ「ABid を 1.0 とした値」を並べて記録するだけで、一致・不一致の判定は達成条件に含めない。

**L5 の比の定義。** 位置 0, 8, 16, 24, 32, 40 × エピソード 0〜3（24 セル）の `score_component` の平均を、同じ手法・同じ 24 セルの既定設定の平均で割る。

## 4. 取る特徴量と、その理由（仮定）

評価の特徴量は REP001 と同じ（`ticks`・`episodes`・`agents`。理由は REP001.md の 4.）。学習ベースで足すものは次のとおり。
「理由」は取る前に置いた仮定で、確かめたものではない。

**仮定1：学習ベースの成績は、学習データの中の行動（誰が、どんな α で入札していたか）に左右される。**
- `DB/train_data/period-N.json`：広告主ごとの予算・CPA 制約・平均の α・最初のティックの α・支払い・購入数・実績 CPA。
  学習データが、どんな手法の記録の混ざりなのかを知るため。

**仮定2：学習が足りているか／発散していないかで、成績が変わる。**
- `DB/models/<model_id>/loss.csv`（1 ステップごとの損失）、`models.loss_last10pct_mean`、`loss_all_finite`、`step_num`。
  既定の 100 ステップが短すぎないかを見るため。

**仮定3：学習の乱数で、重みと成績がぶれる。**
- `models.seed`、`model_sha1`。シードを変えた重みの成績の幅を、手法間の差と比べるため。

**仮定4：学習ベースは、状態にも報酬にも CPA 制約を持たないので、CPA 超過のペナルティを受けやすい。**
- `episodes.real_cpa`、`penalty`、`cpa_exceedance_rate`、`budget_consumer_ratio`（REP001 と同じ列）。
- `ticks.alpha_eff`、`alpha_others_median`：学習ベースが出す α の水準と時間変化。

**仮定5：研究の規模感には、学習の時間も要る。**
- `models.train_seconds`、`runs.sim_seconds`、`bidding_seconds_per_call_mean`。

**再現のための記録。** 学習データの SHA-1、重みの SHA-1、乱数シード、実行コミット、`github/` の版、端末・ライブラリの版。

- 定義の読み替え（判断の基準の変更ではない）：
  - L2 の「重みの SHA-1 が一致」は、保存ファイルの SHA-1 ではなく、**重みのテンソルの SHA-1** で確かめた。torch.jit の保存ファイルには、

## 7. 判断

探索として**達成**。L1（test_01・02 が全件通過）、L2（17 モデルが ok、損失が有限、既定の 5 モデルは学習し直すと同じ重み）、L3（486 run が ok）、L6（欠損なし）の条件を満たし、
L4・L5 の数値を記録できた。L2 と L5 は、5. に書いた読み替えをしている。追加 2 は、事前の決まりに従って BCQ を外した。

言える範囲：この環境（既定の `test.gin`、背景の 47 社は同梱の戦略）、公開データ 21 日分、本家の既定の学習設定、位置 48 × エピソード 0〜3、この端末での結果である。
学習ベースの順位は、学習ステップ数（CQL・TD3_BC）と乱数シード（BCQ）で大きく変わったので、「手法の優劣」としては言えない。
言えるのは、「本家の既定設定のまま学習すると、こうなる」というベースラインの値までである。論文の数値との一致は確かめていない（倍率は一致していない）。

## 8. 得られた事実

条件：既定の `test.gin`（PV 数 500,000）、プレイヤーを 48 社の 1 社の位置に置き換え、エピソード 0〜3、`seed=1`、Linux / Python 3.9.16 / torch 1.12.0（CPU）。
学習は公開データ 21 日分、本家の既定のハイパーパラメータ、バッチ 100。

1. 8 手法の score 合計（192 セル）は、OnlineLP > BCQ > BC > IQL > ABid > PID > TD3_BC > CQL の順で、ABid を 1.0 として 1.51、1.41、1.40、1.39、1.00、0.78、0.002、0 であった。
2. 既定の 100 ステップで学習した CQL は α が 0 で 1 度も落札せず、TD3_BC は α が約 19 で、ほとんど落札しなかった（seed 1・2・3 のすべて）。20000 ステップで学習すると、24 セルの平均 score は CQL 18.6、TD3_BC 21.5 になった。
3. BCQ（100 ステップ）は、seed 1・2 では 24 セルの平均 score が 21.7、seed 3 では 0 であった。seed 1 の BCQ の α の中央値は、ティック 0〜41 で 100.0 のまま変わらなかった。
4. BC と IQL は、seed を変えても成績の比が 0.96〜1.03 に収まった。

## 9. 結果から生まれた問い

- 確かに言えること：本家の既定設定のまま学習すると、BC・IQL・BCQ は OnlineLP の 0.92〜0.94 倍の score で、ABid・PID を上回った。CQL と TD3_BC は、既定の 100 ステップでは落札できず、20000 ステップでは落札できた。BCQ は、seed 3 で成績が 0 になった。
- 今考えていること（確かめていない）：
  - 既定の 100 ステップは、学習には短すぎると考えられる。本家のコードに、試験用の短い値が残っている可能性がある。BCQ の seed 3 の 0 も、100 ステップでは学習が安定しないことの現れである可能性がある。
  - BC・IQL が、CPA 制約を知らないのにペナルティを受けにくかったのは、学習データの α（中央値 81）が、他社の水準に近く、予算を使い切らない入札（消化率 0.74〜0.77）になったためである可能性がある。
  - 論文との倍率の違いは、ABid の成績が論文より高いことから来ている可能性がある（ABid を基準にした相対値なので、ABid が高いと全手法が低く見える）。
- 次に知りたいこと：学習ベースの手法（まず CQL・TD3_BC・BCQ）は、学習ステップ数をどこまで増やせば成績が安定するのか（seed を変えても成績が揃うのか）を知りたい。ベースラインとして使う「学習の長さ」を決めるため。
