## 1. 知りたいこと

**以後の比較に使うベースラインとして、既存 8 手法を、どのパラメータ設定で動かせば公平か。**

- W001 の目的を、「論文の再現」から「以後の作業のベースラインになるパラメータ設定を決める」に変えた（ユーザーと決めた、2026-10-08）。論文には細かいパラメータが無く、数値を合わせることは目的にしない。
- 骨子（研究全体で何を明らかにするか）は、まだ決まっていない（MASTER.md）。このステップは、骨子がどれに決まっても必要になる「比べる相手を正しく動かす」部分である。

**「公平」の定義（この REP で使う。実験の前に決める）。**

| 番号 | 条件 | 理由 |
|---|---|---|
| F1 | 評価に使う日（エピソード 0〜3）の score を見て、パラメータを選ばない | 評価の日に合わせた手法だけが有利になるため |
| F2 | 学習ベースは、学習が落ち着いた重みを使う（出力が、学習を続けても、乱数シードを変えても、ほぼ変わらない） | 学習の途中や、たまたまの乱数で成績が決まると、手法の比較にならないため |
| F3 | 全手法に、同じ情報（公開データ 21 日分）と、同じ決め方を使う。手法ごとに変えるのは、理由を書けるものだけ | 一部の手法だけ手を掛けると、その手法が有利になるため |
| F4 | 変えるのは、理屈かデータの事実から決まるものだけ。それ以外は本家の既定値のままにする | 既定値は著者の選択であり、理由なく変えると「改良した手法」になるため |

## 3. そこから考えたこと

### 3.1 ルールベース 3 手法（PID / ABid / Online LP）：既定値のままにする

- P5 のとおり、PID と ABid には、既定値より良い値がある。しかし、その値は評価の日で測ったものなので、採用すると F1 に反する。
- 理屈で決まる値があるかを考えた。PID の最初の α を「市場の水準」（ログの α の中央値 83）に合わせる案は、P5（15 → 30・60・100 で悪化、5 で改善）と合わない。つまり、「市場の水準に合わせるのが良い」という理屈は、手元の結果に支持されていない。
- ABid の倍率、PID の閾値、Online LP の上限にも、理屈かデータから一意に決まる値が見当たらない（C8、P5）。
- F4 により、**ルールベース 3 手法は本家の既定値のままにする**。これは「調整していない」という設定であり、そのことを明記する。

### 3.2 学習ベース 5 手法：学習の長さを、方策の出力が落ち着くところで決める

P1〜P4 を説明できる仕組みを、材料から 3 つ立てた。

**仮説 A（到達の遅れ）**

| 項目 | 内容 |
|---|---|
| 現象 | P1（100 ステップでは α が小さい。20000 ステップでは落札できる） |
| 仮説 | 出力は 0 付近から始まり（C2）、目標は生の α で平均 82 である（C1、D1）。Adam は 1 回の更新でパラメータを学習率ほどしか動かせない（T1、C3）ので、出力が目標の大きさに届くまでに、数百〜数千ステップかかる。100 ステップ（0.2 エポック、D3）は、その途中で止めている |
| 正しければ見えるはずのもの | プローブに対する α の平均は、ステップとともに 0 付近から増えて、ログの平均（82）の近くで頭打ちになる。頭打ちのあとは、ステップ間・シード間で出力がほぼ変わらない。届く早さは、学習率 × 更新回数が大きい手法ほど早い（BCQ、TD3_BC が先、BC・IQL・CQL が後） |
| 対立仮説なら、どう見えるか | B なら、頭打ちにならず動き続ける。C なら、BCQ の出力は平均ではなく上限に集まる |
| 捨てる基準 | α の平均が、ステップとともに増えない。または、100 ステップの時点で、すでにログの平均の近くにある |

**仮説 B（落ち着かない）**

| 項目 | 内容 |
|---|---|
| 現象 | P4（Q の損失が、学習の途中から増える） |
| 仮説 | Q 値を使う手法は、学習を続けると Q 値の誤差が方策を動かし続ける。特に CQL は、方策をログの α に引き寄せる項が無い（C4）ので、Q 値の形だけで出力が決まり、ステップやシードで出力が動く |
| 正しければ見えるはずのもの | 到達したあとも、同じ状態に対する α が、ステップ間・シード間で動く。動きの大きさは、ログへ引き寄せる項が無い CQL が最大で、Q を使わない BC が最小、という並びになる |
| 対立仮説なら、どう見えるか | A だけなら、到達後は全手法で動きが小さく、手法による並びが無い |
| 捨てる基準 | 到達後の、ステップ間・シード間の出力の差が、CQL でも BC と同じ程度に小さい |

**仮説 C（上限での張り付き。BCQ だけ）**

| 項目 | 内容 |
|---|---|
| 現象 | P2（BCQ の α が 100.0 のまま変わらない。seed 3 は 0） |
| 仮説 | BCQ は出力を ±100 に制限している（C5）が、ログの α の 25% は 100 を超える（D2）。生成モデルの tanh が、大きな目標に引かれて飽和し（T2）、出力が +100 か −100 に張り付く。どちらに張り付くかは学習の初めの動きで決まり、シードで割れる（−100 は、入札が負になり、落札できない） |
| 正しければ見えるはずのもの | BCQ の出力は、絶対値が 99 以上の状態の割合が高い。状態を変えても出力がほぼ変わらない（ログの α との相関が低い）。学習を長くしても、張り付きは解けない |
| 対立仮説なら、どう見えるか | A だけなら、張り付きは学習の初めだけで、長く学習すると、出力が状態に応じて変わるようになる（相関が上がり、99 以上の割合が下がる） |
| 捨てる基準 | 長く学習した BCQ で、絶対値が 99 以上の割合が小さく（ログで 100 を超える割合 25% と同じ程度かそれ以下）、seed 3 も正の値を出す |

A・B・C は、同時に成り立ちうる（手法ごとに、どれが効いているかが違う）。**設定の決め方は、どれが成り立つかで変わる**（5 節）。

## 4. 確かめ方（ループ 1）

**操作**：5 手法 × seed 1, 2, 3 を、本家の既定のハイパーパラメータのまま、長く学習する（BC・IQL・CQL・TD3_BC は 50000 ステップ、BCQ は 1 ステップが重いので 20000 ステップ）。
途中の重みを、100、300、1000、3000、10000、20000、30000 ステップで残す（`params/loop1_train_*.json`）。

**測る量（中間の量）**：学習データから固定の乱数で抜いた 2000 個の状態（プローブ）に、各重みが出す α（`research/src/probe_policy.py`）。シミュレータは回さない。

| 量 | 定義 | 何を見るか |
|---|---|---|
| 平均の α | プローブ 2000 状態の α の平均 | A：0 付近から増えて、頭打ちになるか |
| ステップ間の差 | 同じ seed で、ステップ S の α と、それ以降の各チェックポイントの α の、状態ごとの差の絶対値の平均 | A・B：到達後に動くか |
| シード間の差 | 同じステップで、seed の組ごとの、状態ごとの差の絶対値の平均（3 組の平均） | B・C：シードで方策が変わるか |
| 上限への集中 | 絶対値が 99 以上の状態の割合 | C：張り付いているか |
| ログとの相関 | 状態ごとの α と、ログの α の相関係数 | C：状態に応じて出力を変えているか |
| 0 以下の割合 | α が 0 以下の状態の割合 | 落札できない重みかどうか |

**操作の確認**：最後の重みが、途中で保存しない学習と同じであること（`github/Test/2` の test_03 で確認済み）。BC・IQL の 20000 ステップの重みが、REP002 の重みと同じであること。

**「落ち着いた」の基準（実験の前に決める）**

- 基準の大きさは **α で 5** とする。ログの α の中央値（83）の 6%、標準偏差（53）の約 1/10 に当たる。
  根拠は弱い（「手法間で比べたい差より、十分に小さい」という目安で、REP001 の掃引では α の初期値を 15 から 5 や 30 に変えると score が約 1 割動いた）。**結果を見てから、この値は動かさない。**
- ステップ S が「落ち着いた」とは、次の 2 つを満たすこと。
  1. S 以降のすべてのチェックポイントについて、ステップ間の差（3 seed の平均）が 5 以下。
  2. S 以降のすべてのチェックポイントで、シード間の差が 5 以下。
- 手法ごとに、落ち着いた最小の S を S\* とする。

**最終の成果（判断には使わない）**：score は、このループでは測らない。設定の候補が決まったあと、6 節の「試す」で測る。

## 5. 起こりうる結果と、その先

| 結果 | 分かること | 次の一手 |
|---|---|---|
| R1：5 手法すべてに S\* がある | A が成り立ち、B・C は設定を決めるうえで問題にならない | 学習の長さを、全手法で共通に「5 手法の S\* の最大値」とする（F3）。6 節の「試す」へ |
| R2：BCQ だけ S\* が無く、上限への集中が高い | C が成り立つ。上限 100 が、ログの α の範囲（D2）に合っていない | ループ 2：`max_action` を、データから決まる値（ログの α の 99% 点を切り上げた値）にして、同じ測定をする。`github/` に引数を足す（既定値は 100 のまま） |
| R3：CQL（または他の Q を使う手法）に S\* が無く、出力が動き続ける | B が成り立つ。学習を長くしても、落ち着いた重みは得られない | ループ 2：動く原因を、損失の項から絞る（CQL なら、C4 の「ログへ引き寄せる項が無い」）。理屈で決まる対処が無ければ、その手法は「落ち着かない」と明記し、複数 seed の平均で報告する設定にする |
| R4：BC・IQL にも S\* が無い | 基準（α で 5）が、学習の乱数による自然なぶれより厳しい。または、プローブの取り方が悪い | 基準は動かさない。P3（BC・IQL は score が 0.96〜1.03 倍に収まる）と合わせて、「出力の差 5 は、score の差にしてどのくらいか」を別に測ってから、決め方を見直す |
| R5：仮説 A の捨てる基準に当たる（α の平均が増えない、など） | 100 ステップで落札できない理由は、到達の遅れではない | 学習の長さでは解決しない。重みの読み込み・正規化・推論側のコード（REP002 の未確認事項にある、学習と推論の入力のずれ）を調べる |
| R6：測定が成り立たない（プローブでは落ち着いているのに、6 節の「試す」でシード間の score が大きく割れる） | 学習データの状態と、評価で実際に出会う状態が違う | プローブを、評価のときの実際の状態から取り直す |

## 6. 設定の候補を「試す」（ループの最後に行う。合否の基準は実験の前に決める）

候補の設定で学習した重みを、**評価に使わない日（エピソード 4〜7）**で動かす（F1）。位置 0, 8, 16, 24, 32, 40 × seed 1, 2, 3。

- 合格の条件：(i) 全手法・全 seed で落札している（予算消化率が 0 でない）。(ii) 手法ごとに、3 seed の「24 セルの平均 score」の最大と最小の差が、3 seed の平均の 10% 以内。
  10% は、P3（BC・IQL で 0.96〜1.03 倍、幅 7%）より少し広く取った。
- 不合格の手法があれば、5 節の R3・R6 に戻る（ループをやり直す）。
- 合格したら、その設定を「ベースラインの設定」として確定する（8 節、`research/src/` 直下の json）。評価の日（エピソード 0〜3）での 8 手法の取り直しは、この REP ではしない。8.5 節の、ルールベース・学習ベースの検証のやり直しで行う（2026-10-09、タスク T002 の指示書を書くときに、重なりをなくすため整理した）。

### 7.4 ループ 3 の設計（2026-10-09。学習の前に書いた）

ループ 1・2 の結果（7.1、7.3）を、仮説づくりに使った。対象は BCQ だけ。

**知りたいこと。** BCQ の生成モデルが上限に張り付くのは、**上限 100 が、ログの α の範囲より狭いから**なのか。骨子（1 節）のうち、「データの事実から決まる設定の変更（F4）で、BCQ が状態に応じた出力を出すようになるか」を決める部分。

**手元にある材料（足すもの）**

| 番号 | 種類 | 内容 | 出どころ |
|---|---|---|---|
| M1 | 現象 | BCQ の生成モデルは、学習と同じ経路でも、3 seed とも全状態で上限に張り付いている。seed 1 は、tanh の手前の値が 1000 ステップ以降変わらない。seed 3 は、100 ステップでは負の側（平均 −52）にいて、あとで正の側に移った | 7.3 |
| M2 | コードの事実 | 生成モデルの復元損失は、二乗誤差（`max_action` × tanh(x), ログの α）。x についての傾きは、2 ×（出力 − 目標）× `max_action` ×（1 − tanh²(x)）。出力が上限に近いと、（1 − tanh²）が 0 に近づき、目標が上でも下でも、傾きが消える | `baseline/bcq/bcq.py` |
| M3 | コードの事実 | 生成モデルの最適化は Adam の既定（学習率 1e-3）。`max_action` は `BCQ(..., max_action=100)` の引数だが、学習の入口（`run/run_bcq.py`）からは渡せない | 同上、`run/run_bcq.py` |
| M4 | データの事実 | 学習データ 48,384 行のログの α：100 超が 25.1%、200 超が 2.2%、274 超が 1.0%、300 超が 0.73%。99% 点は 273.6 | 学習データから計算（評価の日のデータではない） |

**考えたこと。** M2 より、目標が上限を超える行（M4：25%）では、出力が上限に達しても誤差が残り、x を上げる向きの傾きが出続ける。目標が上限より下の行は x を下げる向きに引くが、x が大きくなるほど、どちらの傾きも（1 − tanh²）で小さくなる。上に引く力が残り続けるので、x は飽和の側へ進み、進むほど戻る力が消える（M1 の seed 1）。そうなら、上限をログの α のほぼ全部が入る値にすれば、上に引き続ける行がほとんど無くなり（M4：300 なら 0.73%）、張り付かなくなるはずである（C）。
別の説明として、M3 と C1（出力を正規化していない）から、**上限の値に関係なく**、出力の大きさ（`max_action`）× 学習率 1e-3 の更新が、学習の初めに x を行き過ぎさせ、飽和に落ちる、も考えられる（C4。M1 の seed 3 が初めに負の側へ振れたことは、行き過ぎの形をしている）。C4 なら、上限を上げても張り付く。

| 項目 | 内容 |
|---|---|
| 現象 | M1 |
| 仮説 C（上限が狭い） | 上限を超える目標が 25% あり、x を上へ引き続けるので、飽和する。上限を、ログの α の 99% が入る値にすれば、生成モデルは飽和せず、状態に応じた値を出す |
| 対立仮説 C4（初めの行き過ぎ） | 飽和は、上限の値に依らず、学習の初めの更新の大きさで起きる。上限を上げても、新しい上限（+ か −）に張り付く |
| 対立仮説 C3′（生成モデルは直るが、選択で決まる） | 生成モデルは飽和しなくなるが、最終の出力は、Q が最大の候補として上の端が選ばれ、状態に応じない |
| 操作 | `max_action` を 300 にする（99% 点 273.6 を、100 の単位に切り上げた。5 節 R2 の「99% 点を切り上げた値」の、切り上げの単位は書いていなかったので、ここで決めた）。ほかは既定のまま。摂動の大きさは `phi × max_action` なので、5 から 15 に変わる（もとの実装と同じ作り） |
| 操作の確認 | 保存した重みの `max_action` が 300 であること。引数を渡さないとき、これまでと同じ重みになること（回帰テスト） |
| 測る量 | プローブ 2000 状態。(i) 生成モデル（学習と同じ経路）の出力の絶対値が、上限の 99%（297）以上である割合。(ii) 生成モデルの出力（状態ごとの平均）と、ログの α の相関。(iii) 最終の出力 α の、上限への集中・ログとの相関・状態間の標準偏差。(iv) 候補の幅と、選ばれた候補が上の端である割合 |
| 区別する観測 | C：(i) が 0.1 以下で、(ii) が正（0.3 以上）。C4：(i) が 0.9 以上。C3′：(i) が 0.1 以下だが、(iii) の最終の出力のログとの相関が 0.1 未満で、(iv) の上の端の割合が 0.9 以上 |
| 捨てる基準 | (i) ≥ 0.9 なら C を捨てる。(i) ≤ 0.1 なら C4 を捨てる。間、または seed で割れたら、どちらとも言えない |
| 最終の成果 | score は測らない |

**進め方。** 2 段に分ける。3a は、短い学習（3000 ステップ、seed 1〜3、スレッド 4。ループ 1 では、3000 ステップまでに 3 seed とも 97% 以上が飽和した）で、上の区別だけを見る。3b は、3a の結果が C のときだけ行う。

| 3a の結果 | 分かること | 次の一手 |
|---|---|---|
| C（3 seed とも (i) ≤ 0.1） | 上限 100 が狭いことが、張り付きの原因である | 3b：`max_action` = 300 で、共通の長さ（30000 ステップ）まで学習し、ループ 1 と同じ量・同じ基準（α で 5）で S\* を出す。S\* があれば、BCQ の設定の候補にする。無ければ、R3 の扱い（「落ち着かない」と明記、複数 seed の平均） |
| C4（3 seed とも (i) ≥ 0.9） | 上限の値は原因ではない。理屈・データから決まる設定の変更では、張り付きは解けない | BCQ の変更はやめる（同じ原因で 2 回続けて改善しないときは止める、の目安）。**BCQ は既定（`max_action` = 100）のまま**、「状態を見ずに α = 100 を出す」ことを明記して使う。学習の長さは共通にする |
| C3′ | 生成モデルは直ったが、出力は Q の選択で決まる | 3b と同じ学習をして、S\* とログとの相関を事実として出す。設定は、その結果で決める（S\* があれば候補。相関が 0.1 未満なら、但し書きに書く） |
| seed で割れる・間 | 上限の変更は、seed によって効く | 3b と同じ学習をして、長く学習したときに揃うかを見る。揃わなければ、既定のままにして、割れることを明記 |
| 操作の確認に失敗 | 変えたつもりの上限が、変わっていない | コードを直して、やり直す |

**公平について。** この変更は BCQ だけに行う。理由は、上限を持つのが BCQ だけ（C5）で、変える値がデータの事実（M4）から決まるためである（F3・F4）。値を、評価の日の score で選んでいない（F1）。
