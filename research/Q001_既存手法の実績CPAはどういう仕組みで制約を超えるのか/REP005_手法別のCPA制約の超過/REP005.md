## 2. 達成とみなす条件（集計の前に決める）

次をすべて満たしたとき「達成」とする。多い・少ないの判断は、付けない。

| 番号 | 条件 |
|---|---|
| S1 | 8 手法のそれぞれについて、192 セル（48 位置 × エピソード 0〜3）がすべて揃っている。使う run は、すべて `status = ok`、`github_dirty = false` である |
| S2 | 全セルが、下の 4 つの区分のどれか 1 つに入り、手法ごとの合計が 192 になる |
| S3 | 購入数が 1 以上の全セルで、DB の `cpa_exceedance_rate` が、`all_cost ÷ reward ÷ cpa_constraint − 1` と一致する（差の絶対値が 1e-6 以下） |
| S4 | 下の「記録する量」が、8 手法すべてについて、表と図に記録されている |

**セルの区分**（1 セル = 手法 × 位置 × エピソード）

| 区分 | 定義 |
|---|---|
| 超過 | 購入数が 1 以上で、実績 CPA が制約より大きい |
| 制約内 | 購入数が 1 以上で、実績 CPA が制約以下 |
| 購入 0・支払いあり | 購入数が 0 で、支払いが正。実績 CPA が定義できない |
| 購入 0・支払いなし | 購入数が 0 で、支払いも 0（落札していない） |

- 実績 CPA = 支払いの合計 ÷ 購入数（`episodes.all_cost ÷ episodes.reward`）。
- 超過率 = 実績 CPA ÷ 制約 − 1。
- 環境のスコア式は、購入 0・支払いありのセルにもペナルティを掛ける（成績は 0 のまま）。この REP では、「超過」には含めず、別に数える。

**記録する量**

| 量 | 定義 |
|---|---|
| 区分ごとのセル数と割合 | 手法ごと。分母は 192 |
| 超過したセルの割合のエピソード別の値 | 手法ごとに、エピソード 0・1・2・3 の 4 つの値（分母は 48）。ばらつきの目安 |
| 超過率の分位点 | 手法ごとに、購入数が 1 以上のセルの 10・25・50・75・90% 点 |
| 超過の大きさの区間別のセル数 | 超過したセルを、超過率 0〜0.1、0.1〜0.25、0.25〜0.5、0.5〜1、1 超の 5 つに分ける（各区間は下端を含まず、上端を含む） |
| ペナルティ係数 | 手法ごとの平均と、超過したセルだけの中央値 |
| ペナルティで失った報酬の割合 | 1 −（score_component の合計 ÷ reward の合計）。手法ごと |
| 購入数 | 手法ごとの、1 セルの購入数の 10・50・90% 点 |

## 4. 取る量と、その理由（仮定）

「理由」は、取る前に置いた仮定で、確かめたものではない。

- **区分を 4 つにする理由。** 購入数が 0 のセルは、実績 CPA が定義できない。「超過」に入れると、ほとんど落札しない手法（REP003 の CQL、TD3_BC）が、超過の多い手法に見えるおそれがある。
- **超過の大きさの分布を取る理由。** 同じ「超過したセルの割合」でも、少しだけ超えるセルが多いのか、大きく超えるセルが一部にあるのかで、次に立てる問いが変わると考えた。
- **エピソード別の値を取る理由。** 192 セルは、4 つのエピソードの寄せ集めである。手法の間の差が、エピソードの間の差より大きいかを、目で確かめるため。
- **購入数を取る理由。** 購入数が少ないセルでは、実績 CPA が 1 件の購入で大きく動く。超過率を読むときの前提として要る。

## 7. 判断

探索として**達成**。S1〜S4 を満たした。

言える範囲：この環境（既定の `test.gin`、背景の 47 社は同梱の戦略）、REP003 の既定設定（学習ベースは本家の既定のステップ数・seed 1）、位置 48 × エピソード 0〜3、Linux の同じ端末での結果である。
CQL と TD3_BC は、この設定では落札しないので、超過については何も言えない。
「どの手法で超過が多いか」は、数として記録した。差が偶然かどうかの検定はしていない（エピソード別の 4 つの値を並べただけである）。なぜ超過するかは、この REP では扱っていない。

## 8. 得られた事実

条件：既定の `test.gin`（PV 数 500,000）、プレイヤーを 48 社の 1 社の位置に置き換え、エピソード 0〜3、`seed=1`、Linux。学習ベースは、公開データ 21 日分・本家の既定設定で自前学習した重み。1 セル = 手法 × 位置 × エピソード、手法ごとに 192 セル。

1. 落札した 6 手法のすべてで、実績 CPA が制約を超えたセルが、192 セルのうち 72 以上（0.38 以上）あった。
2. 超過したセルの割合は、PID 0.82、ABid 0.85 と、OnlineLP 0.38、BC 0.43、IQL 0.44、BCQ 0.45 の 2 つの群に分かれた。エピソード別に数えても、2 つの群の範囲（0.73〜0.92 と 0.31〜0.50）は重ならなかった。
3. 超過の大きさは、手法で違った。超過率が 0.5 を超えたセルは、PID が 97、ABid が 49、ほかの 4 手法が 16〜21 であった。超過率の中央値（購入のあった全セル）は、PID +0.51、ABid +0.24、ほかの 4 手法は −0.09〜−0.03 であった。
4. ペナルティで失った報酬の割合は、PID 0.45、ABid 0.34、OnlineLP 0.11、BC 0.16、IQL 0.15、BCQ 0.17 であった。
5. 1 セルの購入数の中央値は、6 手法とも 22〜28 であった。
6. 既定設定の CQL は 192 セルすべてで落札せず、TD3_BC は購入のあったセルが 4 つであった。この 2 手法の超過は、数えられなかった。

## 9. 結果から生まれた問い

- 確かに言えること：落札した 6 手法のすべてで、192 セルのうち 0.38 以上が制約を超えた。超過の割合と大きさは、PID・ABid と、ほかの 4 手法とで、はっきり違った。CPA 制約を α の上限に使う OnlineLP でも、0.38 のセルが超過した。CPA 制約を入力にも報酬にも持たない BC・IQL・BCQ の超過の割合（0.43〜0.45）は、OnlineLP に近かった。
- 今考えていること（確かめていない）：制約を入札に使うかどうかだけでは、この並びを説明できないと考えられる。ABid は制約を使うのに超過が多く、BC・IQL・BCQ は使わないのに少ない。また、1 セルの購入数は 20〜30 件ほどで、購入が 1 件増減するだけで実績 CPA が数 % 動く。OnlineLP や学習ベースの「少しだけ超える」セルには、買い方ではなく、購入の抽選のぶれで超えたものが含まれている可能性がある。
- 次に知りたいこと：既存手法の実績 CPA は、どういう仕組みで制約を超えるのか。
